2. 원고 폴더에 접힌 폴더를 열고 닫을때마다 버벅임 발생.

3. 저장을 한 상태로 종료버튼을 눌러도 저장되지 않은 내용이 있다고 팝업이 뜸.(이건 사용자 입장에선 이중 저장 할 수 있게 해서 좋은건가?)

원고 폴더(메인/원고)의 하위 폴더(권 폴더 등)를 펼치거나 접을 때마다 버벅임이 발생해서, 집필모드로 들어갈 때마다 잠깐 멈췄다 들어가지는 증상이 있어. 최근에 만든 좌측 바인더 스플리터/스크롤 작업과는 무관하고, 이 프로그램을 처음 만들었을 때부터 계속 있던 증상이야. 화 개수가 늘어난 지금(1권 25화+2권 진행 중) 더 체감되는 것으로 보여. 원인을 확인하고 고쳐줘.
1. 지연 로딩 캐싱 여부 확인
폴더를 펼칠 때(lazy loading), 이미 한 번 로드한 폴더의 하위 항목 목록을 메모리에 캐싱해두고 재사용하고 있는지, 아니면 펼칠 때마다 디스크(os.listdir 등)를 매번 다시 스캔하고 있는지 확인해줘.

캐싱이 없다면: 한 번 로드한 폴더는 캐싱해서 재사용하도록 고쳐줘. 단, 실제로 파일이 추가/삭제/이름변경된 경우(권 추가, 새 문서 생성, 삭제 등)엔 해당 폴더의 캐시를 무효화하고 다시 로드하도록 해줘.

2. 전체 트리 재구성 여부 확인
폴더를 펼치거나 접을 때, load_tree_data()처럼 트리 전체를 처음부터 다시 그리는 함수가 호출되고 있는지 확인해줘. 만약 그렇다면, 펼침/접힘 이벤트는 그 폴더의 하위 항목만 추가/제거하도록 범위를 좁혀줘 (QTreeWidgetItem을 개별적으로 추가/제거). 원고 폴더 전체(다른 권, 다른 최상위 카테고리 등)까지 다시 그릴 필요는 없어.
3. 병목 지점 특정
가능하면 폴더 펼침 동작 앞뒤로 시간을 측정하는 로그(time.time() 등)를 임시로 넣어서, 실제로 어느 단계(디스크 읽기? 트리 위젯 렌더링? 아이콘 로딩?)가 오래 걸리는지 확인하고 알려줘. 원인 파악 후 그 지점을 중심으로 수정해줘.
테스트: 수정 후 1권, 2권 폴더를 여러 번 펼치고 접어보면서 버벅임이 사라졌는지, 폴더 안 화 개수가 많아져도(예: 2권이 계속 늘어나도) 버벅임이 커지지 않고 일정하게 빠른지 확인해줘.











## 검증 방법
1. 전체 추출 실행 → 결과 파일을 열어서 1화부터 최근 작성한 화까지 순서대로 잘
   들어갔는지, 빈 초안 파일 이후로는 잘 끊겼는지 확인
2. 부분 추출로 임의의 범위(예: 010화~020화) 지정 후 결과 확인
3. 권 경계를 넘나드는 범위(예: 1권 마지막 화 ~ 2권 첫 화)도 정상적으로 이어지는지 확인
4. 추출 후 원본 파일들이 하나도 수정/삭제되지 않았는지 확인


1. 저장할때 전체는 '프로젝트명(1~n화).txt' 부분은 '프로젝트명(n화~m화).txt' 가 기본으로 뜨는 값이고 사용자가 수정할 수 있게 하기.
2. 부분저장시 시작화 끝화 설정을 지금처럼 화살표도 가능하지만 콤보박스 형식도 가능하게.
3. 부분 저장시 뜨는 팝업 UI 크기도 2배로 키워서 화살표 크기도 가독성 좋게.




1. 전체추출 시 47화에서 끊기는데 제목은 생성돼있는 3권(75화)까지로 돼있어. 1~75화라고.
2. 부분추출 시 n~m화.txt 가 돼야하는데 n화~m화 라고 돼있어. 바꿔줘.
