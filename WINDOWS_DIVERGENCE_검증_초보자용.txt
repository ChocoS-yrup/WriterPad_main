============================================================
0. 이 문서에서 확인하려는 것
============================================================

Windows 동기화 장부에는 문서 작업의 상태를 나타내는 기록이 두 군데 있다.

첫 번째 기록:
  sync_operations 표의 status 칸

두 번째 기록:
  sync_operation_events 표에 순서대로 쌓인 사건들

예를 들어 마지막 사건이 committed라면 사건으로 계산한 상태는 completed다.
이때 status도 completed여야 한다.

두 값이 다르면 divergence(상태 어긋남)라고 부른다.

Windows 구현 함수 이름:
  operation_state_divergences()

현재 구현 커밋:
  11ed37bdd1c03bf9ca4b3f1932b659184ec83fc3

현재 구현 커밋의 짧은 이름:
  11ed37b

이 커밋은 2026-08-20에 main과 origin/main에 게시됐고,
GitHub Windows CI에서 전체 테스트 633개가 통과했다.

5. 코드에 divergence 장치가 있는지 확인한다
============================================================

PowerShell에서 실행한다.

  Select-String -Path "sync_v2_store.py" -Pattern "def operation_state_divergences"

정상:
  sync_v2_store.py 안의 함수 위치가 한 줄 출력된다.

현재 기준 위치:
  sync_v2_store.py 약 1041번째 줄

함수의 역할:

  1) sync_operations의 operation_id와 status를 읽는다.
  2) operation_id마다 사건 열을 순서대로 읽는다.
  3) 마지막 사건으로 상태를 계산한다.
  4) 계산 상태와 status가 다르면 결과 목록에 넣는다.
  5) 정상이라면 빈 목록을 반환한다.

정상 결과:
  []

오류 예시:

  [
    {
      "operation_id": "...",
      "stored_status": "pending",
      "derived_status": "completed"
    }
  ]

이 예시는 status 칸은 pending인데 사건은 이미 완료됐다고 말한다는 뜻이다.


============================================================
6. 사건 이름을 상태로 바꾸는 규칙
============================================================

  enqueued             -> pending
  dispatch_started     -> inflight
  retry_scheduled      -> retry_wait
  blocked              -> blocked
  conflict_detected    -> conflict
  committed            -> completed
  replayed             -> completed
  cancel_requested     -> cancelled
  superseded           -> cancelled

마지막 사건과 status가 같은 뜻이면 정상이다.

9. 코드 수준 되감기 불변성을 확인한다
============================================================

정상 되감기는 원본 작업을 덮어쓰지 않는다.

정상 모양:

  원본 operation_id
    원래 content 유지

16. 실제 사건 번호가 연속인지 확인한다
============================================================

Python으로 SQLite 읽기 전용 조회를 실행한다.

아래 명령은 한 줄이다.

  python -c "import os, sqlite3; from pathlib import Path; p=Path(os.environ['WRITERPAD_DIVERGENCE_AUDIT_DB']).resolve(); c=sqlite3.connect(p.as_uri()+'?mode=ro', uri=True); rows=c.execute('SELECT operation_id, MIN(event_sequence), MAX(event_sequence), COUNT(*), COUNT(DISTINCT event_sequence) FROM sync_operation_events GROUP BY operation_id HAVING MIN(event_sequence) <> 1 OR MAX(event_sequence) <> COUNT(*) OR COUNT(*) <> COUNT(DISTINCT event_sequence)').fetchall(); print(rows); c.close()"

정상 출력:

  []

주의:
  위 명령이 경로 문자 문제로 실행되지 않으면 억지로 고치지 말고,
  아래의 SQLite GUI 또는 Python 담당자에게 같은 SQL을 읽기 전용으로 실행해 달라고 요청한다.

검사 SQL 원문:

  SELECT operation_id,
         MIN(event_sequence),
         MAX(event_sequence),
         COUNT(*),
         COUNT(DISTINCT event_sequence)
  FROM sync_operation_events
  GROUP BY operation_id
  HAVING MIN(event_sequence) <> 1
     OR MAX(event_sequence) <> COUNT(*)
     OR COUNT(*) <> COUNT(DISTINCT event_sequence);

결과가 비어 있으면 사건 번호가 1부터 빠짐없이 이어진다.


============================================================
17. 되감기 사건 열을 자세히 출력한다
============================================================

모든 사건을 메타데이터만 출력하는 한 줄 명령:

  python -c "import os, sqlite3; from pathlib import Path; p=Path(os.environ['WRITERPAD_DIVERGENCE_AUDIT_DB']).resolve(); c=sqlite3.connect(p.as_uri()+'?mode=ro', uri=True); rows=c.execute('SELECT operation_id, event_sequence, event_type, error_code, related_operation_id, recorded_at FROM sync_operation_events ORDER BY operation_id, event_sequence').fetchall(); [print(row) for row in rows]; c.close()"

이 명령은 문서 본문을 출력하지 않는다.

되감기한 원본 작업에서 찾아야 하는 순서:

  conflict_detected
  superseded

새 작업에서 찾아야 하는 첫 사건:

  enqueued

새 작업이 서버 전송까지 끝났다면 마지막 사건:

  committed

원본의 superseded 사건에 related_operation_id가 있다면,
그 값이 새 operation_id와 같은지 확인한다.


============================================================
18. Windows 폴더 구조 작업에 대한 특별 설명
============================================================

Windows의 문서 작업:
  sync_operations에 status 칸이 있다.
  따라서 status와 사건 계산 상태를 비교할 수 있다.

Windows의 구조 작업:
  sync_structure_operations에 저장된다.
  별도의 중복 status 칸이 없다.
  사건 열 자체가 상태의 유일한 기준이다.

그래서 operation_state_divergences()는 문서 작업을 검사한다.
폴더 이름 변경·삭제 같은 구조 작업은 다음을 확인한다.

  1) 사건 번호가 1부터 연속인가
  2) conflict_detected가 필요한 위치에 있는가
  3) superseded 또는 committed 같은 최종 사건이 올바른가
  4) 같은 작업이 무한 반복되지 않는가
  5) attempts 횟수가 예상 범위인가

“폴더 divergence 결과가 목록에 안 보인다”는 이유만으로 오류라고 판정하면 안 된다.
