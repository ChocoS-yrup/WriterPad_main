# iPad 전달 — Windows 통합 집필 변경점·차단

후속 상태: 수치·설정 확인까지 반영한 최신 자료는 [최종 실행안 요약](ipad-integrated-execution-final-brief-2026-09-13.md)이다. 추가 대조는 필요 없으며 사용자 실행 승인 전이다. 아래는 이전 구현 보고로 보존한다. 특히 아래 중간 구조 수신 대기 설명은 Windows 동작이며, iPad 통합 후보가 같은 자동 회복을 지원한다는 뜻이 아니다.

기준: `windows-ipad-integrated-work-order-2026-09-13.md`. Windows 로컬 구현·검사 결과이며 iPad 설치/실제 실행 지시나 새 승인이 아니다.

현재 상태: 사용자 전달 `ipad-integrated-editor-windows-note-2026-09-13.md`를 대조했다. iPad 신규 16 + 영향 회귀 269 통과, 후보 `202609130843` 준비·미설치 보고를 확인했다. [통합 실행안 초안](windows-ipad-integrated-execution-draft-2026-09-13.md)에 양측 후보와 시험 위치·ID 제안을 취합했다. 다음은 시험 ID·메모장 정렬 1회 예외·동작 차이·요청 한도·장애 재현 방법의 대조다.

- **변경점:** 여러 문서·폴더 작업, 본문/구조 receipt 복구, 자동 동기화를 연결했다. 기존 계약/RPC와 ID_BASED / epoch 1 유지. 새 통합 후보가 필요하며 기존 단일 문서 후보·23회 상한은 재사용하지 않는다.
- **맞출 동작:** 새 문서의 빈 본문도 그대로 저장/송신한다. 폴더 복원은 해당 삭제에 속한 항목만 복원한다. 상대 구조 작업 중간의 불완전 수신은 부분 반영 없이 다음 전체 수신을 기다린다.
- **실행 한도:** 수동·자동·Auth·handshake·조회·쓰기·복구 요청을 합산하고 요청 총량/시간 한도를 재시작 후에도 유지한다. 모호한 쓰기를 새 ID나 쓰기 RPC 재호출로 복구하지 않는다. 양측 배분·집계 기준은 통합 실행안에서 확정한다.
- **검사:** Windows 통합 32개 + 시작 모드 회귀 11개 통과(묶음 검사 및 실패·영향 범위 재검사, 중복 제외). 실제 통신 없음.
- **후보 준비 완료:** Windows x64 통합 EXE 패키징·격리 시작 검사 2개 통과. 후보 `windows-staging-integrated-editor-20260913-v1`, SHA-256 `35057621d198a6d523e092e6c92942fd410ef8e027db5da4aaa1c3be37490612`. 양측 새 후보 모두 미설치 상태다.
- **차단/미확인:** 양측 실제 receipt SELECT 권한/RLS 미확인. 양측 설치·실기기 확인은 통합 실행안 확정 후 별도 승인 범위에서 진행한다. Windows는 통합 후보 전용 저장소를 사용하며 기존 완료 본문/DB/관문/hold를 보존한다.

회신은 위 공통 동작과의 차이·차단만 부탁드립니다. 차이가 없으면 “공통 기준 일치, 차단 없음”이면 충분합니다. 과거 ZIP이나 완료 왕복을 다시 전달/실행할 필요는 없습니다.
