## 2. 보류 항목을 해소한 근거

수정 전에는 실제 dispatcher가 저장소를 blocked/conflict로 바꾼 뒤 다른 저장소 연결에서 해소하면, coordinator가 최종 허용 snapshot만 볼 수 있었다. 전달된 최초 실패 기록은 문서 blocked→취소 해소 조건에서 이전 준비가 모의 쓰기에 도달했음을 명시한다. 이를 모든 하위 조건에서 수정 전 실패했다고 확대하지 않는다.

이번 `SyncV2ContractQueueHistory`는 다음을 실제 저장소에서 읽는다.

- 작품에 속한 blocked/conflict_detected 사건 및 그 바로 다음 사건의 ID를 정렬해 지문을 만든다. 원고와 폴더 등 `sync_operations`에 속한 작업을 포함한다.
- 동일 SELECT snapshot에서 일반 작업과 계약 배치의 현재 blocked/conflict도 확인한다. 현재 차단 또는 읽기 오류는 허용하지 않는다.
- 별도 읽기 전용 연결을 매번 열고 닫는다. 네트워크 응답을 기다리는 동안 읽기 트랜잭션을 유지하지 않는다.
- sender는 `get_project_status` 전에 승인 지문을 잡고, 상태 응답 직후와 기존 authorize 지점들에서 다시 읽는다. 실제 transport 준비 후 최종 authorize도 포함된다.
- 기존 gate/auth/binding/handshake/scene/global-sync/작품 수명/구조 기준 검사는 유지한다.

이로써 중간 snapshot을 알리지 않아도 저장소에 완료된 차단·해소를 감지한다. 정상 enqueue/dispatch/retry는 차단 바로 다음 사건이 아닌 한 지문을 바꾸지 않는다. batch/operation ID와 payload를 수정하지 않고, 새 준비에서 같은 배치를 재검증할 수 있다.

Windows와 이력 직렬화 형식까지 같을 필요는 없다. 두 지문은 각 기기 내부 승인용이며 서버 계약 payload나 정규 digest가 아니다. 공통 조건은 **차단 진입·이탈이 옛 준비를 무효화하고, 새 준비가 현재 조건을 다시 검사하는 것**이다.

## 3. 회귀 증거와 독립 확인 범위

새 Swift 시험 5개를 읽고 다음 연결을 확인했다.

| 시험 범위 | 검증 방식 |
|---|---|
| 상태 조회 중 미관측 전이 | 실제 recorder·SQLite·dispatcher·coordinator·sender, 문서/폴더 × blocked/conflict, 두 번째 DB 연결에서 해소 |
| 최종 transport 경계 | 실제로 claim된 문서 작업을 markBlocked/markConflict/cancelOperation으로 전이 |
| 실제 충돌 해소 | preserveConflict→해소 원고 enqueue→resolveConflict(manualMerge), 중간 snapshot 직접 전달 없음 |
| 일반 저장 유지 | 실제 원고 recorder enqueue가 상태 조회와 최종 준비 경계에서 발생해도 1회 전송 |
| 읽기 실패 및 새 준비 | DB 없음·현재 차단 거절, 해소 뒤 옛 승인 거절, 새 승인 허용 |

실제 저장 요청의 동등성, 쓰기 0회, 새 준비의 동일 batch 재개를 확인하는 단언이 있다. 최종 transport 시험이 두 번째 dispatcher를 동시에 실행한다고 주장하지 않는다. 구조 기준 초기값은 시험 helper를 사용하고, 실제 pull의 기준 생산 검증은 기존 전체 회귀 범위다.

- 수정 전 별도 실행: **1개 실행 / 실패 1개**. 모의 계약 쓰기 도달로 쓰기 0회 요구 실패.
- 전달된 최종 전체 요약: **962개 / 통과 961 / 실패 0 / 건너뜀 1**. `Scripts/run_tests.sh`, 2026-09-06 11:10:03–11:12:36 KST 시뮬레이터 결과. 메타데이터와 원본 요약의 수치·시각이 일치한다.
- Windows 독립 보조 확인: Swift 제품 소스에서 SQL을 그대로 추출해 임시 SQLite에서 **8건 통과 / 실패 0**. 빈 이력, 정상 이력 유지, blocked/conflict 각각의 진입·이탈과 다른 연결 가시성, 작품 범위, 현재 계약 배치 차단, 반복 조회, 없는 DB의 읽기 전용 실패를 검사했다.
