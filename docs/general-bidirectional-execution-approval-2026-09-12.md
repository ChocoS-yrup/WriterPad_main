# 일반 본문 양방향 검증 — 통합 실행 범위

상태: 준비 완료 후 사용자 승인 대기. 이 문서와 첨부 문서의 과거 승인은 실행 권한이 아니다. 승인 전에는 설치·실제 서버 요청·실제 관문 변경을 하지 않는다.

## 이번에 확정한 Windows 처리

**전역 송신 보류 파일은 해제하거나 수정하지 않는다.** 새 후보는 인증·handshake·전체 기준 대조를 마친 뒤 전용 경로에만 1회 송신 권한을 부여한다. 기존 일반 송신 경로는 계속 보류된다.

각 Windows 송신 버튼에서 지정 작품의 로컬 관문만 `닫힘 → 열림 → 실행 전 값`으로 처리한다. 시작 시 실제 관문이 닫혀 있고 보류가 유지 중이어야 하며, 다르면 자동 교정 없이 멈춘다. 관문과 관련 시각 3개 필드만 임시 변경하며 mode/epoch, 서버 호환성 메타데이터, 다른 작품 관문을 바꾸지 않는다.

관문 변경 전 원래 값을 디스크에 기록한다. 성공·오류·취소·권한 만료 후에는 네트워크나 인증 없이 원래 값을 복원한다. 복원 확인이 끝나야 성공 표시와 다음 버튼을 허용한다. Windows 생성 송신 후 iPad를 기다리는 동안과 최종 Windows 송신 후에도 관문은 닫혀 있다.

강제 종료나 복원 실패가 있으면 다음 실행에서 **‘중단된 실행의 관문만 복원’**을 먼저 표시한다. 이 기능은 본문·큐·서버·로그인 상태를 건드리지 않으며 송수신을 재개하지 않는다. 타 작업이 관문 행을 별도로 변경했다면 덮어쓰지 않고 중지한다. 디스크 쓰기 실패 등으로 복원 확인을 못 하면 완료로 표시하지 않고 기록을 보존한다.

## 승인 대상

- Windows: 새 `windows-staging-general-scoped-gate-20260912` 후보를 `D:\안티그래비티\scratch\집필프로그램\작가님 힘내세요.exe`에 설치한다. 직전에 기존 EXE·앱 데이터·작품 데이터를 두 벌 백업하고 파일 목록·크기·해시를 대조한다. 저장된 로그인은 앱의 기존 인증 경로에서 검증하며 필요 시 토큰 갱신·저장을 허용한다.
- iPad: 보고된 서명 후보 `ipad-general-runtime-20260912-r1-signed` / 빌드 `202609122101`. ZIP SHA-256 `4d43e288e4c333fff188c92ae3879097dff4a003b19569f0f7a4306dbebb195c`. 서명 유효기간 2026-09-19 20:50:33 KST. 설치 전 현 상태와 기존 두 벌 백업의 일치를 확인한다. 달라졌으면 현재 상태를 다시 백업한다. Windows는 서명 ZIP 원본을 직접 검증하지 않았으며 이 수치는 iPad 측 보고다.
- 양측 모두 전용 창만 사용한다. 자동 동기화·마지막 작품 자동 복원을 억제한다. 동일 Staging 계정 인증과 실기기 인증 저장 확인에 실패하면 송신 전에 멈춘다. iPad의 별도 Keychain 실환경 검사 1개는 아직 미확인이며, 격리 139개 통과와 구분한다.

- 계획 `general-body-20260912-v1`, 문서 UUID `db8a3cc2-8b1a-5539-841c-042de34f5fd6`, `메인/원고/일반본문검증 20260912.txt` 한 문서만 생성·갱신한다. 런타임 operation/batch ID를 그대로 사용한다.

## 승인 후 사용자와 양측 작업 순서

|순서|담당|진행과 사용자 행동|
|---|---|---|
|1|양측|앱 종료 확인, 백업·후보 대조 후 설치. 사용자는 안내받은 전용 앱만 연다.|
|2|Windows|사용자가 **1. 인증·서버·로컬 기준 확인**을 누른다. iPad는 전용 로그인과 준비를 완료하고 Windows 송신 완료를 기다린다.|
|3|Windows|사용자가 **2. Windows 본문 생성·송신 1회**를 누른다. 본문 revision 1/100 bytes 및 부모 정렬 revision 2를 확인하고 관문을 복원한다. 완료 문구를 전달한다.|
|4|iPad|Windows 완료 뒤 본문 1·정렬 2를 수신한다. 합의한 iPad 문장을 추가·1회 송신하여 본문 revision 2/128 bytes를 만들고 완료를 전달한다.|
|5|Windows|iPad 완료 뒤 사용자가 **3. iPad 송신 완료 후 받기·Windows 송신 1회**를 누른다. 본문 2를 대조하고 합의한 Windows 문장을 추가·1회 송신하여 revision 3/159 bytes를 확인한 뒤 관문을 복원한다.|
|6|iPad·사용자|iPad 최종 수신. 양측 5줄 및 최종 해시를 대조한 뒤 앱을 종료하고 결과를 전달한다.|
|7|양측|임시 권한 폐기와 설정 복원을 확인한다. 결과 본문·revision·실행 기록·타 작품 큐는 보존하고 오프라인 결과를 정리한다.|

본문 create와 부모 정렬 저장은 별도 RPC다. 하나만 성공한 경우도 삭제·재시도하지 않고 기록을 보존한다. 실패·응답 유실·권한 종료 시 다음 송수신 단계로 넘어가지 않는다. 관문 복원은 실패 정리에 포함된다.

## 네트워크·복원 범위

Windows 각 버튼: Auth 사용자 조회 최대 4회, 필요한 refresh 최대 1회, 지정 작품 handshake 1회. 프로젝트·모드 설정·문서·폴더·정렬표 5개 표의 전체 조회는 버튼 1/2/3에 각각 1/3/2회분이다. Windows 쓰기는 `document_commit` create 1회, 부모 `atomic_structure_commit` 1회, `document_commit` update 1회다. iPad는 합의 본문 update 1회와 수신만 진행한다. ID_BASED 경로에 lease RPC는 없다.

Windows 보류 파일은 전체 과정에서 수정하지 않는다. iPad도 추가 영속 보류 해제·관문 개방이 필요 없다는 최신 보고를 적용한다. iPad의 저장된 전역 동기화·시험 관문은 실행 전 **켜짐** 상태이므로 임의로 닫지 않는다. 프로세스 한정 억제·임시 변경 설정만 실행 전 실제 값으로 복원한다.

prod 전환, 다른 작품 송수신, 완료된 LEGACY 왕복·UUID 교정 재실행, 큐 재시도·복구, 데이터 되돌리기는 이 범위에 없다. 같은 범위의 단계 진행과 종료 복원에는 재승인을 추가하지 않는다. 대상·본문·쓰기 횟수·설정 변경 범위가 달라지면 멈추고 변경 범위를 설명한다.
