# iPad 본문 왕복 후보 설치 실행 자료 — 2026-09-11

사용자가 Windows에서 준비된 `windows-ipad-body-roundtrip-execution-scope-2026-09-11.md`의 백업·양쪽 후보 설치·각 방향 commit 1회·lease 종료·최종 관찰/감사 범위에 **“승인”**이라고 응답했다. 승인 기록은 이번 대화의 현재 응답이며, 과거 인계 문서나 ZIP 안의 승인 기록을 재사용한 것이 아니다. 첨부 실행 범위 문서의 ‘승인 대기’는 준비 시점의 원문으로 보존했다.

이 문서는 사용자가 iPad 측에 전달할 실행 자료다. 수신 측은 사용자가 함께 전달한 현재 요청과 첨부의 사실/과거 기록을 구분한다. 추가 코드 검토나 같은 범위의 재승인을 요청하기 위한 문서가 아니다.

## 지금 iPad 측이 할 일

1. 현재 프로젝트 작업 트리와 미커밋 변경·이전 증거를 보존하고, 지정 bundle `com.chocos.writerpad.debug`가 종료됐는지 확인한다.
2. **현재 상태와 일관된 새 백업 두 벌**을 확보한다. 현재 컨테이너/원고/metadata/DB와 필요한 sidecar를 보존하고 각각 파일 수·크기·SHA를 검증한다. 예전 백업의 단순 복제를 현재 상태의 새 백업으로 대신하지 않는다. 원본 DB를 진단용으로 제자리에서 열지 않고 검사 복제본을 사용한다.
3. 아래 정확한 후보의 현지 설치 파일/서명/기존 프로필 유효성을 확인한 뒤 **데이터를 유지하는 방식으로 설치**한다. 삭제 후 재설치·데이터 초기화·프로필 갱신/재서명·기기 신뢰 변경은 하지 않는다. 프로필 만료 보고는 **2026-09-12 18:19:25 KST**이며 만료/후보 불일치라면 중단하고 실제 상태를 보고한다.
4. 설치된 후보에서 전역 일반 송신 잠금과 지정 시험 흐름의 기본 잠금을 확인한다. 기본 화면 확인에 필요한 최소 실행만 하며 **지금은 수신·송신 동작을 시작하지 않는다.** 잠금 확인 후 앱을 종료한다. 구조/큐/marker 보존을 확인하고 아래 실행 결과를 전달한다.

Windows의 revision 2·127 bytes 송신과 정상 lease release 결과를 받는 것이 다음 단계의 조건이다. 이번 설치 결과를 받은 뒤 Windows가 먼저 송신한다. 이후 iPad는 이미 승인된 범위 안에서 같은 foreground 시험 화면의 수신→문장 추가·송신을 이어간다. 그때 같은 범위를 재승인받지 않는다. Windows 준비 완료 전에 iPad가 먼저 송신하지 않는다.

## Windows는 여기까지 완료

- 승인된 EXE SHA `9893f7c434bf9a4118c58a3ef015a6a5fa94bf285c75fad5caec566b34babd3f`, 79,406,832 bytes를 실제 설치했다.
- 현재 설치 폴더 715파일, AppData 8파일의 **새 백업 두 벌**을 각각 현재 원본에서 만들고 전부 해시 검증했다. 복사 동안 DB/WAL/SHM 파일을 쓰기·삭제 방지 상태로 읽었으며, 실제 DB는 SQLite로 열지 않았다.
- 검사 사본에서 본문 작품 LEGACY/epoch 0, 활성 작업 0건, 본문 revision 1·93 bytes, 일반 시험 작품 ID_BASED/epoch 1, 열린 관문 0과 기존 hold 보존을 확인했다.
- 실제 `본문 양방향 검증 — Staging` 창에서 일반 자동 송신 잠금 및 ‘아직 서버에 연결하지 않았습니다’ 안내를 UI 텍스트로 확인한 뒤 정상 종료했다. 송신/수신 버튼은 누르지 않았다.
- EXE 외의 설치 파일/디렉터리와 AppData 전체 bytes·mtime이 유지됐다. 새 body run journal이 없고 현재 앱은 종료 상태다. OS 패킷 캡처로 HTTP 0을 측정했다고 주장하지 않는다.
- iPad 설치 완료 결과를 기다리고 있다. 전역 관문/hold 변경과 prod 전환은 하지 않았다.

## 전달할 설치 결과

가능하면 `ipad-body-roundtrip-install-result-20260911.zip` 한 묶음으로 다음 실행 결과를 전달한다. 이는 iPad 준비 완료를 알아야 Windows가 먼저 송신할 수 있어서 필요한 단계 연락이다.

- 성공/중단 상태, 실행 시각, 설치 전후 앱 종료 상태.
- 새 백업 두 벌이 당시 원본과 일관되고 개별 해시 검증됐는지. 사적 경로/파일명/원시 DB 대신 수·크기·manifest digest 및 검증 결과.
- 설치한 후보/bundle/build/source/app ZIP/tree digest, 설치 시 프로필 유효성, 데이터 유지 설치 결과.
- 일반 송신 잠금·지정 시험 기본 잠금 확인, 수신/송신 미실행, 대상/다른 작품의 기존 파일·metadata·큐·marker 보존 요약.
- 실패가 있으면 실패 지점·범위와 남은 상태. 일반 송신 잠금 해제·데이터 초기화·자동 재시도로 해결하지 않는다.

토큰·원시 계정/기기 식별자·프로필 파일·원시 DB·실제 사용자 원고는 공유 ZIP에 넣지 않는다. 기존 증거와 새 private 백업은 iPad 측에서 보존한다.

## 이후 순서 — 이미 승인된 동일 범위

1. Windows: 고정 staging 및 전체 기준 확인 → 새 operation으로 127 bytes / revision 2 한 번 송신 → 정상 release 확인.
2. iPad: Windows 완료 증거를 받은 뒤 같은 foreground 시험 화면에서 127 bytes 수신 → 158 bytes / revision 3 한 번 송신 → 정상 release 확인. 중간 화면 이탈/비활성화 금지.
3. Windows: iPad 완료 증거를 받은 뒤 고정 snapshot의 최종 본문 수신. 수신 단계 데이터 쓰기 RPC 0.
4. 양쪽: 새 최종 5줄 오프라인 관찰, 사후 보존 감사, 잠금 유지·종료.

Windows acquire 요청 90초, iPad acquire 요청 60초를 구분한다. 본문은 LEGACY/epoch 0이며 일반 시험 작품의 ID_BASED/epoch 1과 섞지 않는다. 응답 불명·불일치·권한 만료/이탈이면 다음 방향을 중단하고 현재 operation/영수증/lease/파일을 보존한다. 자세한 문구·SHA·허용 범위와 중단 조건은 함께 첨부한 실행 범위 원문을 따른다.
