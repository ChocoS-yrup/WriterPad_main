## 승인 후 사용자 실행 순서

1. **양측 담당 — 설치 준비/설치.** 위 후보·백업을 확인한다. Windows는 EXE만 교체한다. iPad는 지정 서명 후보를 설치한다. 자동 로그인·송수신·앱 자동 실행은 하지 않는다. 담당자가 설치 결과와 종료 상태를 확인한 후 사용자가 시작한다.
2. **Windows — 일반 집필 화면 열기.** 설치 앱을 실행하면 지정 문서만 있는 일반 집필 화면이 열린다. 별도 전용 단계 버튼/설정 메뉴로 이동하지 않는다. 먼저 **「자동저장」 체크를 해제**한다. 이 옵션은 현재 실행 중 메모리에만 적용되며 영속 설정을 바꾸지 않는다. 기존 8줄을 확인한다.
3. **Windows — 수동 저장.** 문서 끝에 위 Windows 수동 저장 한 줄과 Enter 한 번을 추가한다. **Ctrl+S 또는 편집란의 「💾 저장」**을 누른다. `로컬 저장됨 · 송신 대기`를 확인한다. 인증 없이 저장할 수 있다. `큐 등록 필요`, 오류 또는 복구 대기이면 송신하지 않는다.
4. **Windows — 첫 송신.** **「저장된 변경 송신」**을 한 번 누른다. 이 동작의 새 인증/handshake와 서버 기준 확인 뒤 지정 operation만 송신한다. **revision 7 / 314 bytes / 위 해시** 완료를 iPad에 전달한다. iPad는 이 완료 전 수신/송신을 시작하지 않는다.
5. **iPad — 수신과 일반 편집.** 앱 실행 → **「일반 집필 — Staging」** 자동 표시 → 지정 문서 본문 편집란. 설정 메뉴로 들어가지 않는다. **「서버 변경 수신·반영 재개」**를 한 번 누르고 revision 7 / 314바이트 수신을 확인한다. 같은 Staging 계정의 인증이 필요하면 해당 후보의 인증 흐름을 따른다. 수신 성공 후 iPad 추가 한 줄과 줄바꿈을 넣고 상단 **「저장」** 또는 **Cmd+S**로 저장한다. 추가할 한 줄은 한 번에 붙여 넣고 줄바꿈까지 완료하며, 이번 단계 외의 본문 편집은 하지 않는다.
6. **iPad — 송신.** **「저장된 변경 송신 1회」**를 한 번 누른다. **revision 8 / 349바이트 / 위 해시** 완료를 Windows에 전달한다. 그 후 본문을 더 수정하지 않는다.
7. **Windows — 수신과 자동저장.** **「서버 변경 수신」**을 한 번 누르고 revision 8 / 349 bytes와 본문을 확인한다. 「자동저장」 해제 상태에서 마지막 Windows 자동저장 한 줄과 Enter 한 번을 추가한다. 입력을 완료한 뒤 **「자동저장」을 체크**하고 약 1초 기다린다. 이 단계는 Ctrl+S/저장 버튼을 누르지 않는다. `로컬 저장됨 · 송신 대기`를 확인한다.
8. **Windows — 최종 송신.** **「저장된 변경 송신」**을 한 번 누른다. **revision 9 / 393 bytes / 위 해시** 완료를 iPad에 전달한다. 그 후 본문을 더 수정하지 않는다.
9. **iPad — 최종 수신·양측 종료.** **「서버 변경 수신·반영 재개」**를 한 번 누르고 revision 9 / 393바이트 / 최종 11줄 일치를 확인한다. 양측 앱을 종료하고 마지막 완료 revision·해시와 종료 결과를 전달한다. 5분 대기 완료 문구 검증을 다시 하지 않는다.
10. **양측 담당 — 종료 기록 정리.** 닫힌 앱의 기록과 복제본으로 미완료 큐·이번 임시 관문 복원·프로세스 권한 종료를 확인하고 결과를 보존한다. 서버 본문/revision이나 완료 기록은 되돌리지 않는다.

## 실제 요청과 변경 범위

- 기본 본문 쓰기는 Windows 2회, iPad 1회, 합계 3회이며 대상은 위 문서 하나다. 매번 update이고 creation/structure/legacy/lease 쓰기는 없다. 사용자가 저장한 불변 operation 하나씩 처리하며 자동 재송신·전체 큐 drain·자동 주기 수신·Realtime은 열지 않는다.
- Windows 기본 3개 네트워크 동작(송신→수신→송신)은 handshake 3회, 지정 작품의 5개 표 snapshot 3세트(15 GET), document_commit 2회다. Auth/필요한 refresh는 각 새 동작의 제한된 인증 흐름에 포함된다. 로컬 저장·큐 등록·초안 복구 자체에는 HTTP가 없다.
- iPad는 위 명시적 수신 2회·저장된 변경 송신 1회와 그에 필요한 인증/handshake/기준 조회 범위다. 내부 HTTP 총수는 보고에 없으므로 Windows 수치를 적용하지 않는다.
- Windows는 큐 등록 때에만 지정 작품의 `contract_path_enabled`, `contract_path_enabled_at`, `updated_at`을 undo 기록 후 임시 변경하고 송신 전에 정확히 복원한다. 기존 전역 hold는 유지한다. iPad는 영속 관문/설정/보류를 임의 변경하지 않는 공통 기준을 적용한다. 이미 켜진 iPad 관문을 종료 시 임의로 끄지 않는다.
- 새 local recovery 디렉터리와 초안/큐/시도/receipt 기록 및 시험 본문이 생긴다. 모든 이전 증거는 유지한다. Windows 「자동저장」 체크는 실행 중 옵션이며 앱 종료 후 원래 영속 설정을 수정할 필요가 없다.

## 중단·동일 범위 재개

실행 중 네트워크 동작의 창을 유지한다. 오류·무반응·불일치가 있으면 연속 클릭하거나 다음 기기로 진행하지 않는다. 마지막 성공 단계·실제 요청/반영 기록부터 확인한다.

- 완료된 송신은 반복하지 않는다. 인증/준비 만료는 미완료 동작의 권한만 새로 확인한다. 같은 계정·대상·내용·operation의 준비/조회 재개는 이 범위에 포함하며 버튼마다 새 승인을 받지 않는다. 본문 쓰기 횟수는 위 2+1 범위를 유지한다.
- 미시작 HTTP는 기존 기록을 확인한 뒤 같은 operation의 첫 실제 송신을 진행할 수 있다. 응답 유실/성공 여부 불명확은 재송신하지 않는다. Windows **「송신 결과 확인」**은 새 인증/handshake와 원래 batch의 receipt SELECT 최대 두 번으로 확인한다. iPad도 전달된 동일 receipt 조회 규칙으로 해당 후보의 명시적 복구를 사용한다. 부재는 미적용 증거나 POST 허가가 아니다.
- 로컬 저장 후 큐 실패 또는 중단된 임시 관문은 Windows **「로컬 저장·대기열 복구」**로 기록된 범위만 복구한다. 부분 수신은 보존한 snapshot의 미완료 반영만 처리한다. 새로 편집한 초안과 충돌하면 초안을 보존하고 중지한다.
- 오류 복구를 위해 계정/대상/본문 범위·서버 구조·영속 보류를 바꾸거나 요청 ID를 재생성하지 않는다. 이런 변경이 필요하면 현재 실행을 마감하고 별도 범위를 준비한다.

다른 작품, LEGACY 왕복, UUID 교정, 이전 완료 검증 재실행, 일반 자동 동기화 전체 개방, prod 전환은 포함하지 않는다.
