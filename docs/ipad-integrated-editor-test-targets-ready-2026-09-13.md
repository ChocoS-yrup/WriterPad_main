# iPad 전달 — 실제 시험 명세 준비 완료

Windows 후보가 이미 설치된 것을 해시로 확인했다. 사용자 화면 조작으로 시험 항목 5개와 R 본문을 생성·저장했고, 정상 재시작·종료 후 복제본에서 확인했다. **대기 11개(생성 5·정렬 5·본문 1), batch/충돌/실제 요청 0개.** R=48바이트·LF 2개·마지막 LF, E=0바이트이며 계획 본문 해시와 일치한다. 기존 완료 원고·보호 파일은 유지됐다.

전달 파일: [test-targets.json](../_evidence/windows-integrated-editor-execution-20260913/exchange/test-targets.json). 파일 바이트의 SHA-256은 **`9e87ad64aff6e3c4041ca36194a78a736d5f8848fd50293ece7e31bf680adc9f`**다. [체크섬 파일](../_evidence/windows-integrated-editor-execution-20260913/exchange/test-targets.sha256)도 함께 보존했다.

**변경점:** 실제 문서 이름은 `왕복`, `빈문서`이며 `.txt` 접미사가 없다. kind는 document이고 본문·대상 위치·작업 수는 동일하다. 원래 데이터를 이름 변경하거나 큐를 다시 만들지 않았다. R/E 역할을 이 실제 ID·이름에 연결해 대조한다. 빈 B 폴더의 정렬 ID는 계산해 명세에 넣었지만 아직 로컬 정렬 행은 없으며, 이를 이미 생성/송신된 정렬로 해석하지 않는다.

**실행 결합:** 실행 ID `6a7a9c7d-982a-4fcd-90e6-3b4140504860`, 공통 2026-09-13 11:00~12:30 KST(UTC 02:00~03:30), 이전 요청 한도 유지. iPad 실제 시험 ID·명세 해시는 별도 명세로 보존·대조하며 실행 JSON에 추가하지 않는다. iPad가 초기 시험 항목을 새로 만들지 않는다.

**다음 회신은 ‘설치 완료·명세 해시/실제 이름 일치·자동 꺼짐·첫 수신 전 대기’만 필요하다.** 이름 처리 등 차단이 있으면 해당 차이만 알려준다. 대조 후 Windows S1 초기 송신을 먼저 완료하고 그 신호를 받은 뒤 iPad 첫 수신을 진행한다. 현재 Windows는 앱 종료·실행 JSON 미생성·송신 전 상태다. 전체 ZIP·기존 검사 결과는 다시 보내지 않는다.
