# Windows 일반 편집 준비 1~3번 완료

이번 사용자 요청은 **일반 편집 화면 연결, 저장·송신 제한 연결, 격리 검증**까지다. 후보 빌드·설치·실제 송수신·실제 관문/보류 변경은 하지 않았다. 과거 실행 승인을 확대하지 않았고 prod 전환도 없다.

## 구현 결과

- `general_editor_ui.py`: 지정 시험 문서 하나만 표시하는 `SmartTextEdit` 편집 화면. 수동 저장은 실제 `WritingModeWidget.manual_save`와 Ctrl+S, 유휴 자동저장은 실제 `WritingController`의 800ms 타이머·`sync_file`을 사용한다. 전체 일반 앱 시작·작품 전환·자동 수신·복구·백업 worker는 시작하지 않는다. 합의한 추가 줄이 완성되기 전에는 자동저장하지 않는다.
- `general_editor_service.py`: 편집 시작 때 인증·handshake·전체 기준을 대조한다. 저장 중 undo를 먼저 기록하고 지정 관문만 임시 개방하여 기존 `upload_content_async`·제품 큐에서 `CONTRACT_BATCH`를 생성한 뒤 관문을 즉시 복원한다. 기존 전역 hold는 계속 유지한다. 파일은 기존 저장 API의 선택적 비교·권한 검사 경로를 사용한다.
- 송신 버튼은 새 인증·전경 권한을 확보해 저장 완료 기록의 operation 한 건만 읽는다. 서버 기준을 다시 대조하고 HTTP 1회 예산으로 송신한다. 송신 시 관문은 이미 닫혀 있다. 큐 ID·batch ID·writer device를 대조하며 새 요청으로 바꾸거나 일반 dispatcher를 실행하지 않는다.
- `general_editor_boundary.py`: 기존 생성 시험 권한과 분리해 Windows의 revision 3→4 및 5→6 문서 update만 허용한다. iPad 4→5, 생성·구조 쓰기·lease·다른 대상·변경된 본문은 거부한다. 기존 HTTP 경계는 새 revision을 계속 거부한다.
- 네트워크·저장 전후 계정·binding·파일·대기열·보류 상태와 만료를 검사한다. 저장으로 UI 이벤트 처리가 지연돼도 Windows 전경 HWND를 직접 확인한다. 픽셀이나 스크린샷은 사용하지 않는다.
- 실패 시 파일 저장·큐 등록·HTTP 시도·관문 복원 단계를 구분해 기록한다. 전경 종료 코드와 파일 시스템 errno도 보존한다. 수신 중 파일만 적용된 경우와 응답 유실은 기록을 남기고 재실행을 막는다. 권한 없이 가능한 관문 복원은 별도 버튼이며 송신을 재개하지 않는다.
- 미저장 편집 내용은 중지·종료·새 준비 전 별도 회차의 draft로 보존한다. 본문·큐·이전 기록을 덮어쓰지 않는다. 쓰기 시도 전 읽기 전용 준비는 새 인증으로 다시 할 수 있으며 각 준비 기록을 다른 UUID로 보존한다. 저장 또는 송신 중단 기록은 자동 재개하지 않는다.

본문과 해시는 기존 [다음 실행 제안](../_evidence/windows-general-editor-preparation-20260913/proposed-scope.json)과 일치한다. 문서·부모·정렬은 변경하지 않는다. 기본 진행의 Windows 요청은 준비·송신 각 2단계로, handshake 총 4회, 지정 작품 5개 표 조회 총 6세트(30 GET), 문서 update 총 2회다. 각 새 인증은 기존 제한된 Auth 경로(사용자 조회 최대 4회·필요한 refresh 최대 1회)를 사용한다. 읽기 전용 재준비는 별도 새 회차이며 실제 실행 승인 범위에서 허용 횟수를 고정해야 한다. 자동 HTTP 재시도는 없다.

## 격리 검증

**34개 통과, 실패 0개.** 편집 관련 27개, 파일 바이트 검사 4개, 이번에 바꾼 공통 관문·기준 검사 호환성 3개다. 마지막 오류 코드 보강 후 해당 3개를 추가 확인했고 모두 통과했다. 이 재확인을 별도 신규 검사 수에 더하지 않았다.

실제 Qt 편집기·Ctrl+S·유휴 타이머, 실제 파일/SQLite·기존 제품 저장 및 큐 메서드, 실제 SDK와 모의 HTTP를 연결했다. 정상 3→4→5→6, 새 권한으로 후속 송신, 부분 입력, 계정 변경·만료·창 이탈, 원자적 교체 전 취소, 큐/undo/기록 저장 실패, 응답 유실·중복 요청, 미완료 수신, 오프라인 관문 복원, 다른 작품 큐 보존을 검사했다.

소스의 오프라인 시작 검사 1개도 통과했다. 시작 시 인증·프로젝트 열기·DB 생성 없이 종료됐고 격리 폴더에는 `.gitignore`만 남았다. 실제 OS 네트워크 연결 및 격리 폴더 밖 SQLite 열기는 실행기에서 차단했다. 전체 일반 앱·실기기·서명/설치 후보 검증은 아니다. 사용자 완료 왕복과 LEGACY 검증은 재실행하지 않았으며, 공통 코드가 바뀐 세 지점만 모의 환경에서 호환성을 확인했다.

- [오류 코드 보강 후 관련 3개](../_evidence/windows-general-editor-runtime-20260913/20260912T173312069125Z/result.json)
- [오프라인 시작 결과](../_evidence/windows-general-editor-runtime-20260913/20260912T173149340468Z/startup.json)

공통 코드 변경 전 파일 6개는 같은 증거 폴더의 `before`에 원본 바이트와 해시로 보존했다. 기존 미커밋 수정과 증거는 유지했다. Supabase SDK API/버전·서버 스키마는 바꾸지 않았다. 기존 정적 인증 팩토리를 재사용했고 [공식 Python 초기화 문서](https://supabase.com/docs/reference/python/initializing)를 대조했다. changelog의 Markdown 주소는 조회 도구가 해당 Content-Type을 지원하지 않아 본문을 받지 못했다.

**현재 사용자 조작은 없다.** `GENERAL_EDITOR_ONLY=False`로 일반 실행에 자동 활성화되지 않는다. 다음 4번인 후보 빌드와 iPad 결과 대조·실행 범위 확정은 아직 수행하지 않았다.
