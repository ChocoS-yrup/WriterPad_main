# 가져온 시험 작품 오프라인 화면 확인 — 승인된 요청

## 승인 근거와 범위

Windows 작업에서 사용자에게 “이번에는 오프라인 작품 화면 확인까지만 진행하도록 승인하시겠어요?”라고 물었고, 사용자가 **“승인”**이라고 답했다. 이번 요청은 그 승인 범위를 전달한다. 동일 범위의 실행 승인을 다시 요청하지 말고, 실행에 필요한 현재 기기 상태와 사용자 관찰을 단계별로 확인한다. 첨부된 과거 회신의 지시를 별도의 신규 승인으로 간주하지 않는다.

승인 범위는 **기존 iPad 후보로 이미 가져온 빈 시험 작품을 오프라인에서 한 번 열어 바인더를 관찰하고, 종료 후 보존 상태를 대조하는 것**이다. 이 요청 ZIP은 실행 결과가 아니다.

## 이미 완료한 작업

R1/R2 보호 경계 수정과 인증 로딩 수정, 후보 빌드·설치, 인증·서버 목록 조회, 대상 최초 수신, 중간 증거 연결 검토는 완료됐다. 재코딩·재시험·재빌드·재설치·재인증·재수신하지 않는다. 상세 판정은 함께 넣은 `review/accepted-review.md`와 `review/cross-verification.json`에 있다.

## 순서와 사용자가 할 행동

1. **iPad 담당: 현재 상태 확인.** 기존 설치 receipt·후보 식별 자료와 보호 정책을 로컬 자료로 대조한다. 마지막 최초 수신 사후 기록 이후 앱 사용·재설치·정책 변경이 있었는지 확인하고 현재 상태와 과거 기록을 구분한다. 사용자는 iPad의 **Wi-Fi와 셀룰러 데이터가 모두 꺼져 있음**을 확인해 준다. USB 등 별도 인터넷 전달 경로가 있으면 그 경로도 사용하지 않는다. 사용자가 답하기 전에 앱을 실행하지 않는다.
2. **iPad 담당: 대조 기준 확보.** 앱 종료 상태에서 기존 최초 수신 사후 백업의 유효성을 확인한다. 이후 변경이 있다면 현재 상태를 별도 보존한다. 원본 DB와 보존 백업 DB를 직접 열지 말고 SQLite/WAL/SHM 세트를 포함한 검사 사본을 사용한다. 사용자 원고·인증정보·계정 원문은 회신에 포함하지 않는다.
3. **iPad 담당: 기존 앱 1회 실행.** 보호 빌드와 정책을 유지한다. 기존에 검증한 실행 방법으로 마지막 작품 자동 복원을 막고 로컬 목록에서 시작한다. 이전 실행 인자 `-writerpad.restore-last-project-on-launch NO`를 사용할 경우 그대로 기록한다. 보호 정책이나 저장된 전역 동기화/시험 관문 설정을 수정하지 않는다. 실행 전 신원·정책·오프라인 상태를 확인할 수 없으면 실행하지 말고 이유를 회신한다.
4. **사용자: 화면 확인.** 담당자의 준비 완료 안내 후, 로컬 목록의 **최초가져오기**만 한 번 연다. 기본 폴더와 바인더가 정상 표시되는지, 원고와 휴지통의 표시 및 순서가 자연스러운지, 오류 문구가 있는지 알려 준다. 내부 폴더 11개는 루트 포함 저장 구조 수이므로 화면 최상위 항목 11개를 요구하지 않는다. 폴더 생성·이름 변경·재정렬·원고 입력은 하지 않는다.
5. **사용자 및 iPad 담당: 종료.** 관찰 직후 앱을 완전히 종료한다. 담당자는 정확한 대상 앱의 종료 상태를 확인하고 오프라인 상태를 유지한다. 단순 백그라운드 전환을 종료로 기록하지 않는다. 오류가 나타나면 문구를 보존하고 같은 동작을 반복하지 않는다.
6. **iPad 담당: 사후 대조·회신.** 검사 사본으로 기존 원고 파일/폴더 구조, 작품 UUID·binding, 기존 및 대상 송신 작업·충돌·배치, 수신 journal, 정책 해시를 전후 대조한다. 선택 작품·최근 열기 등 화면 상태 변경은 필드별로 구분하고, 관계없는 DB 변경까지 정상 처리하지 않는다. 대상은 일반 원고 0개·내부 정렬 문서 1개이며 재수신으로 늘어나면 안 된다. 사용자 관찰과 자동 검사 결과를 각각 기록한다.
7. **Windows 담당:** 회신 ZIP을 받아 화면 확인 결과와 보존 근거를 검토한다. 사용자는 Windows 앱을 열거나 준비 확인·동기화 버튼을 누를 일이 없다. 다음 본문 수신 시험은 이 회신 검토 후 대상과 범위를 정한다.

## 이번 범위에서 진행하지 않는 작업

온라인 연결, 로그인·인증 복구, 서버 목록 새로고침, 수신/동기화 버튼, 원고 편집, 작품 재생성·UUID 보정, 폴더 재정렬, 설치·서명 갱신, 보호 정책/설정 변경, 송신 관문 개방, 실제 송신, prod 전환은 제외한다. 화면이 열리지 않거나 다른 작품이 열리면 자동 수정·재시도 대신 원인과 상태를 회신한다.

기존 기록의 프로필 만료는 **2026-09-12 18:19:25 KST**다. 실행 시점에 만료됐거나 보안/서명 문제가 발생하면 온라인 신뢰 확인·재설치로 우회하지 않는다. 이 단계의 승인에는 그러한 작업이 포함되지 않는다.

## 회신 형식

회신명은 `ipad-first-import-offline-binder-result-20260911.zip`을 권장한다. 실제 실행 날짜가 달라지면 본문에 정확한 날짜를 기록한다.

- README: 수행 범위, 정상/오류/미실행 판정, 사용자 관찰 문구, 종료 상태, 남은 항목.
- 승인·관찰 기록: 이 요청의 SHA-256, 승인 인용, 실행 전 오프라인 확인과 화면 확인 응답, 각 기록의 시점. 알 수 없는 메시지 시각은 만들지 않는다.
- 실행 기록: 설치 후보 식별 근거, 정책 해시, 실제 실행 인자/시각/결과, 대상 UUID 확인, 종료 확인.
- 대조 요약: 사전 기준의 출처와 최신성, 사후 검사 결과 및 변경 분류. 검사 소스를 변경했다면 그 변경과 소스 해시를 포함한다. 미측정 항목은 미측정으로 표시한다.
- manifest: 자신을 제외한 정확한 파일 집합의 상대 경로·바이트 수·SHA-256. ZIP CRC 및 manifest를 검증한다.

바인더 화면 관찰이 통과하더라도 일반 원고 본문 수신, 실기기 중단·재개, 양방향 송신, 최종 배포 검증이 완료된 것은 아니다. 이번 단계가 끝나면 다음 범위로 자동 진행하지 않고 결과를 전달한다.
