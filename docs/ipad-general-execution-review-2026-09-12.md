1. 양측 후보 식별과 백업 확인 후 설치. iPad의 두 벌 백업 각 815개 파일 일치는 보고 결과로 기록한다. Windows 백업·설치와 실제 관문·보류 처리 절차는 아직 실행하지 않았다.
2. 전용 경로만 사용하고, 자동 동기화·마지막 작품 자동 복원을 억제한 상태에서 동일 Staging 계정 인증 및 실제 저장 확인. 인증 실패는 송신 전 중지한다.
3. Windows 기준 확인 → 지정 작품에 필요한 관문·보류의 제한 변경 → 본문 1 및 부모 정렬 2 송신 → iPad 수신·본문 2 송신 → Windows 수신·본문 3 송신 → iPad 최종 수신·양측 대조.
4. Windows는 현재 후보가 열린 관문과 명시적인 `released` 보류 기록을 요구한다. 후보 자체에는 이를 변경·복원하는 기능이 없다. 기존 일반 화면용 관문 제어기는 일반 관리자를 요구하므로 전용 후보에서 그대로 호출 가능한 것으로 간주하지 않는다. 이 제한 변경·복원 절차의 구체화가 Windows 측 남은 준비다.
5. 종료 시 임시 권한 폐기, 임시 변경한 관문·설정·보류만 실행 직전 값으로 복원. 본문·서버 revision·실행 기록·타 작품 큐는 보존한다. iPad에 관문 닫기를 추가하려면 별도 변경 항목으로 실행 범위에 명시해야 한다.
