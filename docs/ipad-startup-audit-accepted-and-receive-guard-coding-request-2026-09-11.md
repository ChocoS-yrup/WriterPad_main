## 필수 구현

1. **시작 전 기본 차단:** 서비스/task/SDK 네트워크 경로를 시작하기 전에 정책을 만든다. 별도 작은 정책 저장소는 원자 저장과 버전 검증을 제공하며 누락·손상·읽기/저장 실패는 차단이다. 오류 때문에 정상 정책을 지우거나 기존 설정을 초기화하지 않는다. 정책 파일이 없어도 새 프로세스는 자동 인증/조회/송신을 하지 않는다. 영구 정책에는 쓰기 허가를 저장하지 않는다.
2. **이번 모드는 서버 자료 쓰기를 항상 거절:** legacy commit_document/commit_folder, ensure_project, atomic_structure_commit/document_commit, lease acquire/renew/release 및 새로 발견한 원격 쓰기 경로를 목록화하고 공통 보호를 적용한다. 미래 쓰기 허가 생성·해제 UI·타이머 해제는 구현하지 않는다. 기존 계약 gate/epoch/authorize는 제거하지 않고 추가 조건으로 조합한다.
3. **기존 큐 보호:** start/recover/claim/retry/foreground/login/network 이벤트와 직접 drain 진입을 보호한다. 읽기용 로그인·binding 조회가 pending/retry_wait/inflight/conflict, attempts, batch/event 이력과 초기 snapshot 큐를 바꾸지 않게 한다. 정책 거부를 네트워크 실패로 처리해 재시도/오류 상태를 쓰지 않는다. 이미 존재하는 큐·충돌을 취소/완료 처리하거나 삭제하지 않는다. 독립적인 진단 기록은 보호 대상 DB/원고와 분리한다.
4. **인증과 읽기의 명시적 허가:** 새 프로세스의 초기 상태는 읽기도 불허다. 사용자의 전경 동작으로만 해당 실행의 인증 허가를 만들고, 그 허가는 예상 canonical Staging endpoint·정책 revision·실행 식별자·만료/취소 문맥을 가진다. 로그인 전에는 검증된 계정 UUID가 없으므로 임의 UUID를 신뢰하지 않는다. 인증 결과의 계정이 예상 시험 계정과 일치한 뒤에만 계정별 읽기 허가로 전환한다. 시험 계정/작품 값은 나중에 별도 확정되며 이번에는 합성값을 주입해 검사한다.
5. **재시작·계정/endpoint 변경·로그아웃·화면 이탈/비활성화·취소/만료에서 허가 소멸:** 자동 복구나 저장된 전역 true로 읽기 허가를 되살리지 않는다. 앱 자체 refresh/retry와 SDK의 암묵적 session refresh도 같은 허가 범위에서만 동작해야 한다. 일괄 HTTP POST 금지/허용이 아니라 인증 동작, 허용 SELECT/읽기 RPC, 서버 자료 쓰기를 의미별로 구별한다. 토큰/세션 원문은 진단에 기록하지 않는다.
6. **최종 전송 경계와 늦은 응답:** SDK transport와 별도 URLSession/HTTP client가 같은 정책을 받는지 점검한다. 미분류 요청·허용되지 않은 origin/경로/redirect는 거절한다. 서비스 입구만 막지 말고 전송 직전과 응답 적용/수신 공개 직전에도 문맥·revision을 재검사한다. 취소된 in-flight 응답으로 기존 DB/원고가 바뀌지 않게 한다. 이미 외부로 나간 요청을 되돌렸거나 0회였다고 기록하지 않는다.
7. **기존 수신 경로 재사용:** 목록은 허용된 계정, 신규 수신은 별도로 선택한 서버 UUID와 그 journal/로컬 binding으로 제한한다. raw binding store와 lease/legacy recorder 없는 기존 puller를 사용한다. 선택 작품 수신을 위한 새 로컬 journal/폴더/문서/baseline 저장은 필요하므로 전역 로컬 쓰기 금지로 깨뜨리지 않는다. 기존 다른 작품·큐는 그대로이며, 중단 재개는 같은 ID/journal로 수행하고 검증 완료 후에만 목록에 공개한다.
8. **화면:** 검증 모드의 송신 잠금 상태를 표시한다. 금지된 전체 동기화·서버 등록/연결/이름 변경·전송 버튼은 비활성화하고 service 직접 호출도 거절한다. 수신 검증 준비를 위해 전체 동기화를 켜게 하지 않는다. 모드나 정책 내부 구현을 일반 사용자 화면에 불필요하게 노출하지 않는다.

정책 객체를 actor나 공유 상태로 만들 때 async 중단점에서 허가가 취소될 수 있음을 반영한다. UI/SDK 한 군데만 막거나 전역 defaults를 false로 읽는 것만으로 위 조건을 충족했다고 판단하지 않는다. 개별 store 진입점까지 필요한 보호 범위는 실제 호출 경로로 정하고 기존 로컬 수신 트랜잭션과 구별한다.

## 격리 검증 및 합격 기준

실제 사용자 DB/Keychain/홈 디렉터리/기기/서버를 쓰지 않는다. 임시 정책 저장소·합성 DB·fake 인증/transport·제어 가능한 시계/취소 지점을 사용하고 외부 네트워크는 차단한다. 아래는 검사 시나리오이며 임의의 고정 테스트 개수 자체가 합격 기준은 아니다.

- 인자 없는 두 독립 프로세스 문맥, 전역 true/관문 true, 정책 정상/누락/손상/지원 버전 불일치/저장 실패 각각에서 자동 인증·자동 읽기·원격 쓰기 0, 기존 보호 행 불변. 첫 문맥의 읽기 허가를 두 번째가 재사용하지 못함.
- start/active/auth/network 동시 이벤트, 로그인 성공, retry/claim/FORBIDDEN 복구, binding 조회·초기 snapshot, 직접 drain 진입에서 기존 pending/conflict/retry_wait/inflight·이력/attempts 불변.
- legacy/ensure/계약/lease 모든 transport 직접 호출을 검증 모드에서 거절. `releaseAll`·늦은 heartbeat·정리 task도 포함. 기존 일반 모드의 계약 gate/epoch 조건은 유지.
- 인증 허가가 없으면 restore/refresh/SDK 필요 시 갱신도 0. 허가가 있으면 필요한 인증 동작만 실행하며 계정 불일치·endpoint 혼동·redirect·미분류 요청은 차단.
- 허용된 계정의 목록 및 선택 작품 수신은 fake transport로 성공. 선택 외 UUID, 계정/endpoint/revision 변경, 취소/만료, 응답 적용 직전 취소는 보호 자료를 바꾸거나 수신 완료를 공개하지 못함.
- 수신 저장 실패·중단·재시도는 같은 journal/ID를 유지하고 검증 완료까지 숨김. 기존 이름 충돌·손상 identity·기존 미완료 로컬 변경 처리와 다른 작품 불변을 유지.
- 저장 오류/차단이 네트워크 오류 재시도 기록으로 섞이지 않음. 정책 거부 횟수와 실제 fake transport 호출 수를 별도로 집계하고 보호 대상 행/원고 전후 해시로 확인.
- 검증 모드를 쓰지 않는 기존 구성의 동작에 회귀가 없는지 관련 테스트를 실행한다. 이번 변경이 닿는 기존 회귀 검사는 필요한 만큼 다시 실행하되, 전체 57/22/100개를 단순 수용 목적으로 일괄 반복하지 않는다. 이 구조 변경 뒤 관련 회귀를 전혀 실행하지 않는 것도 허용하지 않는다.

각 필수 경로와 대응 시험을 표로 연결하고 인증 호출 수·목록/수신 호출 수·자료 쓰기 호출 수·기존 큐 변경 수를 분리한다. HTTP fake 0만으로 모든 시작 경로가 검사됐다고 쓰지 않는다. Swift XCTest를 실제 실행한 결과와 코드 검토만 한 항목을 구분한다.
