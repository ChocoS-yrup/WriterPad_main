# Windows 독립 조회 헤더 차이 — 오프라인 수정 완료

2026-09-14. 사용자 “다음 진행”은 직전 제시한 오프라인 재현·필요한 수정·신규 검사 범위에 대한 지시로 처리했다. 실제 토큰 접근·서버 요청·재조회·인증 갱신·설치·관문 변경은 하지 않았다.

**결과: 응답 쿠키가 다음 요청에 자동으로 붙을 때 이전 코드의 Q2 HEADERS_CHANGED가 재현됐다. 해당 쿠키 전파를 차단하고 안전한 진단을 추가했다. 신규 11건 전부 통과, 실제 I/O 경계 접근 시도 0건이다.**

실제 종료 run `a2e05f32-2387-430d-a46b-0c0fc5aec0b0`은 Q1 HTTP 200 뒤 Q2 전송 전 중단됐고, 기존 기록에는 헤더 차이·응답 쿠키가 없다. 이번 재현은 같은 실패를 일으키는 경로를 합성 자료로 입증한 것이며, 그 실제 실행에서 쿠키가 원인이었다고 소급 확정하는 것은 아니다. 서버에서 수정 효과를 확인한 상태도 아니다.

## 변경

- `isolated_read_collector.py`: 각 요청 생성 전에 해당 HTTPX 클라이언트의 메모리 쿠키를 비운다. 응답 Set-Cookie가 다음 요청의 Cookie로 전파되지 않는다. Windows/browser 저장소나 기존 인증 토큰은 건드리지 않는다.
- `isolated_read_launcher.py`: 기존 헤더 완전 일치 검사는 유지한다. 차단 시 `header_difference`로 누락·값 변경·중복된 허용 헤더 이름, 알려진 추가 Cookie 헤더 및 알 수 없는 헤더 개수를 기록한다. 헤더 값과 알 수 없는 헤더 이름은 기록하지 않는다. 알 수 없는 이름 자체에 비밀정보가 들어 있을 가능성도 차단한다.
- 새 진단은 launcher 반환값과 launcher-journal의 종료 이벤트에만 추가한다. 수집기의 observation 형식, count 기준, Q1~Q7 목록, 계정/프로젝트, 전송 한도, 종료 기록 및 iPad의 기존 미검증 판정은 그대로다.

## 신규 검사와 보존

검사 파일은 `tests/test_isolated_read_header_fix.py`다. 기존 검사의 합성 fixture 구성 함수만 재사용했으며 기존 test 메서드나 완료 suite는 실행하지 않았다.

검사한 11개 경우:

1. 보존한 수정 전 수집기에 합성 Set-Cookie 응답을 넣어 Q2 차단·예약 2/전송 1을 재현. 동일 ID 재사용 거부 확인.
2. 매 응답이 쿠키를 설정해도 수정 후 7개 요청 전부 Cookie 없이 통과. Authorization·Prefer/count 조건 유지.
3. 첫 요청 전 메모리에 있던 합성 쿠키도 전송하지 않음.
4. 요청 생성 후 명시적으로 주입한 Cookie는 여전히 차단하고 값을 기록하지 않음.
5. Authorization 변경은 계속 차단하며 토큰 값 비공개.
6. 알 수 없는 헤더는 이름과 값 대신 개수만 기록.
7. API key 누락 차단 및 누락 이름 진단.
8. 알려진 헤더 중복 차단 및 이름 진단.
9. 알 수 없는 헤더 중복은 이름 대신 개수로 진단.
10. 쿠키를 포함한 HTTP 401 응답 후 추가 요청·갱신 없음.
11. 쿠키를 포함한 redirect 응답을 따라가지 않음.

검사는 임시 폴더·합성 세션·HTTPX MockTransport만 사용했다. socket 연결/DNS, 실제 HTTPX transport, keyring/WinVault 읽기·쓰기·삭제, WinDLL 및 SID 접근을 차단했으며 차단 경계에 도달한 시도도 0건이다. 기존 인증 갱신 검사와 기존 53/21/24건 검사는 다시 실행하지 않았다.

증거 폴더: `_evidence/windows-read-header-fix-20260914/`.

- `before/`와 `before-source-hashes.json`: 수정 전 수집기·호출부 원문 보존.
- `test-results.txt`, `result.json`: 신규 11건 통과, 실제 I/O 0건, 검사 전후 기존 파일 hash 일치.
- `code-hashes.json`: 다음 새 실행에서 사용할 최종 실행 소스 pin. 기존 승인 manifest나 종료 실행 pin을 수정하지 않았다.

기존 종료 조회의 Q1 원문·감사·사용량·만료, 종료 인증 실행과 설치물·원본·기존 미커밋 변경을 보존했다. 종료 run의 사용량 환급·만료 연장·재개는 하지 않았다.
