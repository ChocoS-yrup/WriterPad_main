# iPad 교정 검토 회신의 시험 요약 해시 보완 요청 — 2026-09-11

이 문서는 검토 자료다. 서버 교정·실기기 실행·수신 재개·marker 정리·설치·송신·관문 개방 승인이 아니다.

Windows 수신 ZIP SHA-256:
`37706877e77bbce051f03516784c70cb5f47664539b81cb40eb960c8509090d2`

manifest 18개 파일을 검증했고 추가 테스트 역패치/동결 원문/합성 원고/정렬 content/폴더 11개의 식별자도 대조했다. 두 XCTest의 통과 기록과 로그·코드는 일치한다. 같은 journal 재개 시 올바른 UUID만 제공해야 하며, 기존 잘못된 marker는 보존해도 된다는 조건을 수용한다. Windows에서는 원본 DB 복사본의 교정 8건과 FK 모델 5건을 통과했고 실제 데이터 교정은 아직 실행하지 않았다.

보완할 사항은 다음 한 가지다.

- `isolated-test-result.json`의 `xcresult_summary_sha256`: `fbc6a3a25b1f07e8a975cab1e4817c2db11a9a74998fefb15cd95b75160b36f8`
- 첨부 `xcresult-summary.json`의 실제 SHA-256: `4ececc09d81115712823139c6525d54e5be489fd0f00e8e6ca72bef8be29855f`
- manifest는 실제 첨부 파일과 일치한다.

원시 xcresult 요약과 공유용 축약/정제 요약이 다른 것이라면, 보존된 원본을 읽어 실제 해시와 변환 방법 및 공유 파일 해시를 구분해 회신해 달라. 오래된 참조라면 원본 보존 자료에서 정확한 참조로 고친 작은 정정 파일을 제공해 달라. 이전 ZIP을 덮어쓰지 말고 이번 ZIP SHA와 원본 기준을 명시한다. 원시 자료가 없다면 확인 불가능한 범위를 그대로 적는다.

완료된 빌드/XCTest 재실행, 실제 iPad 연결·조회·실행·종료, marker/journal/owner 변경, 설치/재서명, 서버 조회/쓰기, 재개 버튼 조작은 이 보완을 위해 필요하지 않다. 비공개 계정·기기 식별자·토큰·원고·프로필을 첨부하지 않는다.

사용자는 이 요청 ZIP을 iPad 작업에 전달하기만 하면 된다. 실제 교정 완료 결과는 Windows에서 별도로 제공하며, 그 전까지 기존 종료·오프라인 상태를 유지한다.
