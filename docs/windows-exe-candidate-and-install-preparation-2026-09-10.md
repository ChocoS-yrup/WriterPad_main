# Windows EXE 후보 및 설치 준비

2026-09-10. 사용자님의 ‘진행’에 따라 수용된 소스를 포함한 Windows EXE 후보를 별도 경로에 제작했다. 후보 파일 검증과 설치 절차 준비까지 완료했으며, 현재 설치 앱은 교체하지 않았다.

빌드는 원본 작업 트리에서 88개 입력·검증 파일을 보존한 별도 source 디렉터리에서 기존 `작가님힘내세요.spec`으로 수행했다. 빌드 캐시·임시 파일·출력도 이번 evidence 디렉터리로 분리했다. 의존성 설치나 제품 소스 수정은 하지 않았다.

- iPad 수용 manifest 16개가 현재 소스와 일치한다. R1~R3 기록의 18개 파일은 그대로이며, 공유 파일 `main.py`는 이후 수용된 관문 UI 연결 버전을 포함한다.
- EXE archive 안의 제품 모듈 58개와 `main` 시작 코드를 추출해 보존 소스의 컴파일 결과와 비교했다. 중첩 코드 객체를 비교하며 파일 경로만 정규화했다. 제품 코드를 실행하는 검사는 아니다.
- AI 응답 보존·작품 백업 UI와 checkpoint·관문·명시적 보류 해제 관련 모듈이 모두 들어 있다. Qt MSVC 런타임 8개와 리소스 4개도 확인했다.
- 기존 성공 빌드의 누락/제외 모듈 경고 이름 379개와 동일하다. 새 경고 이름이나 누락된 로컬 제품 모듈은 없다. 모든 선택 기능의 실행 성공을 뜻하지는 않는다.
- 후보 EXE의 `--qt-import-smoke-test`가 Windows Qt 플랫폼에서 종료 코드 0으로 끝났다. 이 분기는 제품 모듈·프로젝트·인증 초기화 전에 종료한다. 숨김 실행, 별도 자료·AppData·임시 경로를 사용했고 프로젝트/동기화 자료 디렉터리가 비어 있음을 확인했다.
- 기존 Python 독립 복구 묶음을 검증한 뒤 `candidate/independent-recovery/`에 함께 준비했다. 현재 소스와 바이트가 같고 이전 검증 결과를 재사용한다. Python 3.11이 필요한 소스 도구이며, 별도 복구 EXE를 새로 만든 것은 아니다.

기존 R1~R3 기능 검사, 130개 checkpoint/관문 관련 검사와 이후 purge 5개 검사를 반복하지 않았다. 새로 확인한 것은 빌드 산출물·포함 소스·Qt 시작 경계다. 실제 설치 DB의 8012→8013 업그레이드와 새 앱 전체 화면·로그인·실제 송수신은 아직 확인하지 않았다.

`D:\안티그래비티\scratch\집필프로그램\작가님 힘내세요.exe`를 읽기 전용으로 해시 확인했다. 기존 `cd7ccebf125864b63ac8a9552585c44221e1086d0e6fc3e2617c6fa89a12fd89`와 일치한다. 이번 후보와 별도 파일이다. 기존 설치본이나 실제 작품·DB·송신 보류 파일을 수정하지 않았다.

## 설치 전 준비 절차 — 현재 실행하지 않음

설치와 실제 자료 업그레이드가 허용된 후 아래 순서를 적용한다. 후보 ZIP은 설치 프로그램이 아니며, 풀어서 일반 실행하면 프로젝트·인증 초기화가 시작될 수 있으므로 현재 검토 단계에서는 실행하지 않는다.

1. **사용자: 저장 후 Windows 앱 정상 종료.** 미저장 원고와 AI 응답을 먼저 파일로 보존한다. 이후 작업자는 실행 중 프로세스가 없는지 확인하고, 바로가기/실행 프로필의 자료 루트·AppData 재정의 여부를 확인한다. 지금 앱을 종료할 필요는 없다.
2. **Windows: 같은 시점의 원본 사본 확보.** 기본 대상은 설치 폴더 `D:\안티그래비티\scratch\집필프로그램` 전체와 `%LOCALAPPDATA%\AntigravityWriter` 전체다. 프로필에서 재정의된 경로가 있으면 실제 경로를 함께 보존한다. 작품목록·설정·폰트·identity·휴지통·백업, 기존 EXE, 동기화 DB·존재하는 WAL/SHM·보류 표식·검토/중단/성공 기록을 누락하지 않는다. 링크·junction·파일 변화가 있으면 그대로 진행하지 않고 대상과 일관성을 확인한다.
3. **Windows: 사본 검증 및 복구 기준 고정.** 실제 경로 바깥의 새 비공개 로컬 보존 폴더에 복사하고 파일 목록·크기·SHA256을 대조한다. 동기화 DB는 앱 종료 후 일관된 상태로 확보한다. WAL이 남아 있으면 DB 파일만 단독 복사하거나 원본 WAL을 삭제하지 않는다. 검사는 사본에서 수행하며 원본은 보존한다. 토큰을 출력하거나 Windows 자격 증명 저장소를 추출하지 않는다. 이 자료는 iPad 전달 ZIP·Git에 넣지 않는다.
4. **Windows: 실제 자료의 사본에서 8013 업그레이드 확인.** 제품의 DB store 초기화만 별도 프로세스·사본 경로에 연결해 수행하고 네트워크를 차단한다. `PRAGMA integrity_check`, `user_version=8013`, 기존 테이블의 행·보호된 원본/두 stopped/성공 회차·영수증·이벤트·다른 작품·관문·큐 보존, 새 permit 테이블의 빈 상태를 대조한다. 이 단계에서 서버 checkpoint 수용이나 mode/epoch 전환은 하지 않는다. 합성 DB의 upgrade/rollback 검사는 이미 통과했지만 실제 자료 사본 확인을 완료했다고 대체하지 않는다.
5. **Windows: 설치 직전 상태 확인 후 후보 배치.** 후보와 기존 설치본 해시, 프로세스 종료, 사본 무결성을 다시 확인하고 허용된 설치 범위에서만 교체한다. 설치와 첫 일반 실행을 분리한다. 기존 관문 및 송신 보류 상태를 평가하고, 실제 통신이 아직 허용되지 않았다면 앱 전체 실행으로 자동 인증·수신·재시도가 시작되지 않게 실행을 보류한다. Qt smoke 통과는 전체 앱 실행 허가를 대신하지 않는다.
6. **실패 시 복구:** 새 앱을 종료하고 새로 생긴 자료도 별도 보존한 뒤, 원인을 확인한다. 업그레이드된 DB에 이전 EXE만 덮어씌우거나 `user_version`만 8012로 내리지 않는다. 송신 전 복구는 검증한 동일 시점의 EXE·DB·자료 묶음을 기준으로 한다. 서버 작업이 시작된 뒤에는 단순 로컬 되돌리기로 처리하지 않는다.

현재 백업 UI의 작품 묶음은 로그인·앱 전역 설정·송신 큐·실행 기록을 의도적으로 제외한다. 따라서 위 설치 복구용 전체 로컬 사본을 작품 백업 하나로 대체하지 않는다. 사본의 송신 큐는 실제 앱에 연결해 실행하지 않는다.

## 이후 양쪽 순서와 사용자 행동

| 단계 | Windows | iPad | 사용자 행동 |
|---|---|---|---|
| 현재 후보 준비 | 빌드·검증 완료 | 추가 코드 확인 불필요 | 앱 조작·재전달 불필요 |
| 설치가 별도로 허용된 후 | 위 자료 보존·업그레이드 사본 확인·배치 | 현재 상태 유지 | 안내받은 시점에 저장·정상 종료 |
| 실제 준비/수신이 허용된 후 | 지정 Staging 작품의 동일 집필 manager에서 준비·fresh pull, DB 8013 및 ID_BASED/epoch 1 확인 | 기존 대상 작품 상태 확인 | 단계별 결과를 보고 다음 버튼 안내에 따름 |
| 관문·송신이 허용된 후 | 폴더 11개·순서표 12개·계약/digest·C9·빈 큐 확인 → 작품 관문 → 명시적 보류 해제 | 해당 시험 작품만 준비 | 전역 동기화 임의 활성화 금지 |
| 첫 양방향 원고 시험 | 합성 원고 Windows→iPad 먼저 | 수신 확인 후 iPad→Windows | 한 방향 결과 확인 후 다음 방향 진행 |

iPad의 전역 동기화 저장값은 회신상 true이며 마지막 프로세스 인자만 NO였다. 재시작 후 OFF로 가정하지 않는다. 다른 작품의 대기 4건·충돌 3건은 별도로 보존하며 현재 전역 동기화를 켜지 않는다. 이미 끝난 서버 migration/관리 배치와 과거 고정 계약 시험은 반복하지 않는다.

이번 결과는 설치·실제 송신·관문 개방·prod 전환을 허용하지 않는다. 사용자님의 기존 금지가 유지된다. 원격 CI·커밋·푸시·병합도 수행하지 않았다.
