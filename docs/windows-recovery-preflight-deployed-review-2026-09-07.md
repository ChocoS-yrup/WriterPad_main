## 다음 단계의 최소 변경안

현재 `check_server_ledger`는 복구 adapter의 진행 사건을 기록하며, sender에서는 회차 claim 이후 호출된다. 기존 준비 상태 조회는 네트워크를 호출하지 않는다. 따라서 어느 버튼도 현재 로그인 API 점검을 대신해서 누르면 안 된다.

새 범위는 다음과 같이 구체화할 수 있다.

1. 기존 원장 RPC 입력·응답 검증을 DB 쓰기 없는 공통 읽기 함수로 분리하고, 기존 복구 adapter의 사건 기록은 기존 위치에 유지한다.
2. 앱 현재 로그인 클라이언트와 작품·계정 연결을 캡처하여 원장 API만 독립 조회하는 경로를 추가한다. 원본 요청/고정 식별, 닫힌 관문, 현재 계정 일치를 확인한다. 새 nonce를 사용하고 조회 전후 연결·계정·관문 변경을 검사한다. claim·sender 전체 호출·관문 setter·외부 토큰 갱신은 사용하지 않는다.
3. 읽기 결과 및 오류를 비밀정보 없이 메모리에 보관하고 작품 밖으로 내보내는 UI를 추가한다. 기존 stopped 기록이나 복구 회차를 쓰지 않으며 조회 결과를 승인으로 취급하지 않는다.
4. 새 읽기 경계만 격리 검증하고 빌드를 준비한다. 설치 파일과 검증 근거가 준비된 뒤에만 사용자에게 앱 종료를 요청한다. 설치 전후 원본·기존 실행·닫힌 관문·복구 회차 0개를 확인하고, 설치한 앱의 실제 로그인으로 읽기 버튼만 사용하도록 안내한다.
5. 실제 로그인 결과를 iPad에 반환한다. 실제 복구 회차 생성·송신·재전송은 그 뒤에도 별도 새 승인 범위다.
