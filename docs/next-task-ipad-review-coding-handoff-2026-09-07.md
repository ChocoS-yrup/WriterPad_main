## 새 창의 진행 순서

1. 사용자 첨부 iPad 회신과 이 인계·감사 보고를 읽는다. ZIP은 원본을 보존하고 workspace 내 새 전용 경로에 안전하게 읽거나 추출한다. 경로 이탈·덮어쓰기를 피하고 CRC/제공 manifest를 확인한다. 보고서가 어떤 코드·발신 ZIP을 기준으로 답했는지 기록한다.
2. R1~R4별로 양쪽 합의, 기존 완료, 새 결함, 근거 부족을 구분한 짧은 대조표와 한정된 완료 조건을 작성한다. 구현할 일과 실기기 확인만 남은 일을 분리한다. 일반적인 “전부 다시 검증” 단계는 만들지 않는다.
3. 사용자 코딩 지시 범위 안에서 확정된 Windows 수정과 필요한 격리 검증을 진행한다. 기본 순서는 R1, R2, R3이며 R4는 회신에서 확인된 실제 결함·의존성에 맞춘다. 제품 변경이 생기면 그 영향에 맞는 기존 검사와 새 실패 경계 검사를 선택한다.
4. 코드·검사 결과·미실행 항목·사용자 다음 행동을 정리한다. iPad 확인이 필요한 변경은 구체적인 검토 대상과 근거로 묶는다. 설치나 실제 통신 단계는 필요한 결과를 먼저 준비한 뒤 사용자 지시 범위에 맞춰 진행한다.

회신이 아직 없으면 수신됐다고 꾸미거나 과거 첨부로 대신하지 않는다. 사용자가 회신을 첨부할 때까지 대조·의존 코딩은 대기한다. 이 인계 준비만으로 앱 조작을 요청하지 않는다.
