# 합성 원고 1개 최초 수신·본문 확인 — 승인된 iPad 요청

## 승인과 완료 범위

Windows 작업에서 “이 iPad 수신·본문 확인 범위도 승인하시겠어요? 실제 송신·관문 변경·설치는 제외합니다.”라고 물었고 사용자가 **“승인”**이라고 답했다. 이 직접 승인은 아래 지정 작품의 기존 후보 실행, 동일 Staging 인증·목록 조회, 최초 수신 한 번, 오프라인 본문 관찰, 종료 후 자료 대조까지다. 같은 범위의 승인을 다시 요청할 필요는 없으며, 현재 기기 상태와 사용자 관찰은 필요한 시점에 확인한다.

Windows의 새 작품 생성·초기 업로드는 완료됐다. `originals/windows-nonempty-initial-upload-result-20260911.zip`을 바이트 그대로 동봉했다. SHA-256은 `14b9c67bb1905e7231e2219b45fba9da39e2c63064e23bff8395047d9068fe49`다. 그 내부의 ‘iPad 미승인/미실행’ 표시는 Windows 결과 작성 당시의 기록이다. **현재 실행 승인은 바깥 authorization.json과 이 문서에 기록된 새 사용자 응답**이며, 과거 문서의 지시 자체에서 승인을 도출하지 않는다.

R1/R2·인증 로딩 수정, 후보 빌드/설치, 빈 작품 최초 수신과 바인더 확인, Windows 시험 자료 준비를 반복하지 않는다. 이번 ZIP도 실행 결과는 아니다.

- 작품: **본문수신검증 20260911**
- 서버 작품 UUID / 최초 수신 시 새 로컬 UUID: **`9a78c51c-7de9-43a8-be54-d25a22d08a28`**
- 일반 원고: `메인/원고/1권/1화.txt` **1개**
- 원고 UUID: `502cdbe7-814c-42f8-8ed4-81c40cd94902`
- 경로상 ‘1권’ 부모 폴더 UUID: `1de12e60-f998-48b9-aae9-7675b4b42fb9`
- 본문: UTF-8, BOM 없음, LF, 마지막 줄바꿈 포함, **93 bytes**
- SHA-256: `cdfcc92e4b06906d9c54e11b4ad263cf913105fdff7669ac5b69b1f42bb7f96d`
- 서버 본문 revision 1, 폴더 11개·각 revision 1, 내부 경로 정렬 문서 1개·revision 1, UUID tree_orders 0행.

원본 결과 ZIP의 `target-baseline.json`에 전체 폴더 UUID/부모/이름과 정렬 payload, 문서별 해시가 있다. `fixture/nonempty-receive-synthetic.txt`가 정확한 본문 기준이다. 제목만으로 대상을 선택하지 않는다. 기존 **최초가져오기** 및 **일반동기화 검증 20260910**는 이번 대상이 아니다.

서버 원고 `parent_folder_id`와 `structure_revision`은 실제 **null**이다. 이를 위 경로상 부모 UUID나 숫자 1로 바꿔 기록하지 않는다. 최종 수신 코드는 폴더 baseline과 상대 경로로 로컬 원고의 부모를 정한다. 검사에서는 서버 snapshot 장부의 null과 로컬 메타데이터의 실제 부모 UUID를 구분한다. 이 시험을 UUID 구조·정렬 전환 검증으로 확대하지 않는다. 수신 코드가 이 기준을 수용하지 못하면 서버를 교정하거나 모드를 전환하지 말고 중단한다.

## 진행 순서와 사용자가 할 행동

1. **iPad 담당 — 준비:** 요청 ZIP과 동봉 원본의 CRC·manifest·해시를 검증한다. 사용자는 최근 앱 사용·미저장 자료 여부와 **Wi-Fi/셀룰러 데이터가 꺼져 있음**을 알려 준다. 필요한 저장은 시험 시작 전에 정리한다. 호스트 인터넷 전달 경로도 사용하지 않는다. 사용자 상태 확인 전 앱을 실행하지 않는다.
2. **iPad 담당 — 사전 기준:** 기존 설치 등록/receipt·정책을 대조하고 앱 종료 여부를 확인한다. 예상 밖 프로세스 존재, 종료 후 재등장 또는 등록/정책 변경이 있으면 실행을 중단하고 현재 상태를 회신한다. 종료·실행을 반복하지 않는다. 자료 최신성을 확인해 기존 보존 자료를 활용하고, 변경이 있으면 종료 상태에서 현재 기준을 별도 보존한다. 원본 및 보존 DB는 그대로 두고 SQLite/WAL/SHM 검사 사본을 사용한다.
3. **iPad 담당·사용자 — 실행 및 수신 준비:** 기존 후보를 한 번 실행한다. 검증된 `-writerpad.restore-last-project-on-launch NO`로 로컬 목록에서 시작한다. 사용자는 안내에 따라 **서버 작품 가져오기**를 열어 **송신 잠김** 표시를 확인한다. 담당자가 준비 완료를 알리면 Wi-Fi만 켜고 앱으로 돌아와 **수신 준비**를 한 번 누른다. 필요한 로그인은 기존 동일 Staging 계정으로 앱에 직접 입력한다. 비밀번호·토큰을 대화나 회신에 넣지 않는다.
4. **사용자·iPad 담당 — 대상 확인:** 목록에서 **전체 UUID `9a78c51c-7de9-43a8-be54-d25a22d08a28`**와 **미가져옴** 상태를 확인한다. 이름만 일치하거나 가져옴/연결 충돌/예상 밖 중단 상태이면 진행하지 않는다. 로컬 이름 충돌이 있으면 임의 별칭이나 binding 해제로 우회하지 않고 회신한다.
5. **사용자 — 최초 수신 1회:** 해당 행의 **이 iPad로 가져오기**를 한 번 누른다. 완료까지 앱을 전경에 유지한다. 반복 클릭·화면 이탈·의도적인 연결 중단을 하지 않는다. 완료 문구와 가져옴 상태 또는 오류 문구를 알려 준다. 실패/취소/5분 허가 만료 시 자동 재개·재수신하지 않는다.
6. **사용자 — 오프라인 본문 관찰:** 완료되면 먼저 Wi-Fi를 끄고 셀룰러도 꺼져 있음을 확인한다. 담당자의 안내에 따라 새 작품의 **원고 → 1권 → 1화**를 열고 아래 합성 문장이 정상 표시되는지 알려 준다. 빈 작품의 화면 확인을 반복하는 단계가 아니다. 입력·편집·이름 변경·재정렬·저장 버튼 조작은 하지 않는다.

   ```text
   본문 수신 검증 20260911
   이 문서는 동기화 시험용 합성 원고입니다.
   끝.
   ```

7. **사용자·iPad 담당 — 종료:** 관찰 후 앱을 완전히 종료한다. 담당자는 정확한 실행 PID/등록 경로와 종료 상태를 확인한다. 단순 백그라운드 전환을 종료로 기록하지 않는다. 종료 후에도 Wi-Fi/셀룰러가 꺼져 있는지 사용자에게 확인받고 근거를 기록한다.
8. **iPad 담당 — 사후 검사:** 종료 상태의 사후 자료를 보존하고 검사 사본에서 아래 기준을 대조해 결과 ZIP을 만든다. 앱 내 결과 내보내기 버튼이 있다고 가정하지 않는다. 완료 문구와 사용자 본문 관찰은 바이트/DB 검증과 구분한다.

## 사후 검사 기준

- 새 로컬 작품·binding 각 1개, local/server 작품 UUID 일치, 수신 출처 표식 1개, 미완료 수신 journal 0.
- 일반 원고 1개 및 내부 정렬 문서 1개를 별도로 집계. 일반 원고 UUID·상대 경로·로컬 부모 UUID가 고정 기준과 일치.
- 실제 TXT UTF-8 바이트 93 및 hash 일치, snapshot 장부 revision 1 및 base hash 일치. 서버 구조 필드 null은 원문대로 기록.
- 폴더 11개의 UUID·부모·이름·revision과 실제 로컬 계층을 비교. 내부 경로 정렬 payload 및 hash와 UUID tree_orders 0행을 구분.
- 새 작품의 송신 queue/batch/conflict 0. 기존 원고/파일/연결/UUID/큐/충돌/정책/설정 보존. 새 작품 추가와 최근 선택·커서·화면 상태·경로/mtime 반영은 실제 변경 필드별로 분류하고, 다른 변경을 일괄 정상 처리하지 않음.
- 기존 자료와 검사 원본의 해시 보존, DB 무결성·FK, 오프라인 복귀 및 앱 종료 기록. 라디오/API/HTTP 전수 계측을 하지 않았다면 그 한계를 명시.

오류·바이트/revision 불일치·예상 밖 변경·송신 잠김 누락·다른 계정/UUID·서명 문제이면 수정/재수신/관문 변경 대신 증거와 종료 상태를 회신한다. 이미 완료한 Windows 업로드를 다시 실행하도록 지시하지 않는다.

## 회신 및 범위 종료

권장 회신명: `ipad-nonempty-first-receive-result-20260911.zip`. README, 요청 해시/승인 근거, 현재 후보/정책/사전 자료 확인, 사용자 관찰 원문과 기록 시각, 실행/종료 기록, 개인정보 없는 전후 상태·바이트 비교·변경 분류, 사용한 감사 코드와 해시, SHA-256 manifest를 포함한다. 정확한 메시지 시각을 모르면 만들지 않는다. 실제 DB·사용자 원고·계정/기기 식별자·토큰·프로필은 공유하지 않는다.

이번 승인에는 **iPad 실제 송신, 원고 편집, 기존 큐 처리, 관문 변경, 설치/서명 갱신, prod 전환, 의도적인 중단·재개 시험**이 포함되지 않는다. 수신/본문 확인이 끝나면 결과를 Windows에 전달하고 다음 단계로 자동 진행하지 않는다. Windows 사용자는 앱을 추가 조작할 일이 없다.
