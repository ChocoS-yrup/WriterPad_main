# Windows 작품 백업·독립 복구 안내

이번 작업은 소스 수정과 합성 자료 검증까지다. 현재 설치된 EXE에는 아직 새 화면이 반영되지 않았다. 지금 실제 작품으로 백업·복원을 시험하거나 앱을 교체할 필요는 없다.

## 새 백업 화면

향후 이 소스가 반영된 앱에서는 시작할 때 **프로젝트 선택 → 작품 선택 → 작품 백업·복구**로 들어간다. 작품을 열거나 서버 작품 관리로 들어갈 필요가 없다.

1. 다른 창에서 편집 중이면 먼저 저장한다. 화면에만 있는 미저장 내용은 백업 대상이 아니다.
2. **선택 작품 백업 만들기**에서 외부 저장소의 상위 폴더와 새 폴더 이름을 고른다. 기존 폴더는 덮어쓰지 않는다.
3. 완료한 폴더 전체를 보관한다. `windows-manifest.json` 하나만 복사하면 백업이 아니다.
4. **백업 폴더 검증**에서 해당 폴더를 고르면 목록·크기·SHA-256과 작품 구조를 확인한다.
5. **새 독립 폴더에 복원**은 현재 작품이 아닌 새 자료 루트를 만든다. 복원 원고는 그 안의 `작품목록/<작품명>`에 있다. 현재 앱이나 서버에 자동 연결하지 않는다.

생성·복원 중에는 완료까지 기다린다. 파일 선택 취소는 작업을 시작하지 않는다. 쓰기 오류·원본 변경·내용 불일치가 생기면 완료로 표시하지 않고 기존 자료를 보존한다.

## 포함 범위와 호환성

| 데이터 | 처리 |
|---|---|
| 집필모드 활성·휴지통 원고, 빈 폴더, UUID·부모·제목·순서 | 포함. 기존 v1 core와 실제 프로젝트 adapter 재사용 |
| `메인/`, `AI/`, `백업/`의 저장된 AI 원고·응답 이력·사본 | 포함 |
| 작품 `설정.json`, `cost_history.json` | 포함 |
| 집필모드 설정과 `백업/`의 자동저장·충돌·복원전 사본·휴지통 원위치 정보 | 포함 |
| `.writerpad/identity-v1.json` | 보존. 정상 복원은 기존 adapter가 identity를 구성하며 UUID를 유지 |
| 로그인·앱 전역 설정·서버 연결 표식·송신 큐·소모된 검토 요청·진행 중 journal | 제외. 이전 실행이나 송신을 재생하지 않음 |
| 숨김/임시 파일, 지정한 사용자 데이터 영역 밖의 파일 | 제외 목록에 기록. 임의 보조 파일까지 모두 보관한다고 주장하지 않음 |
| 미저장 편집 내용, 메모리에만 남은 AI 응답 | 제외. 먼저 저장해야 함 |

Windows 묶음은 `windows-manifest.json + windows-data/ + portable-v1/`이다. **공통 v1의 manifest나 계약 버전은 바꾸지 않았다.** `portable-v1/`는 기존 원고·구조 패키지이고, Windows 추가 자료는 바깥 묶음에 둔다. iPad에서 이 Windows 묶음 전체를 직접 복원하는 기능은 검증하지 않았다. iPad 개발에서는 공통 v1만 별도로 취급해야 하며, Windows 추가 자료를 버린 채 전체 자료 복원 완료로 표시하면 안 된다.

정상 백업은 identity가 맞고 진행 중 journal이 없는 작품에 대해 생성한다. 레거시 작품을 자동 승격하거나 원본 journal을 재생하지 않는다. 구조가 손상됐거나 legacy 상태라면 다음의 **자료 사본 보존**을 사용한다.

복사 전후 전체 포함 목록·해시·파일 변경 시각을 비교하고, 복사본의 구조도 확인한다. 동시 변경이 발견되면 백업을 공개하지 않는다. 실행 중인 다른 프로그램의 쓰기를 강제로 잠그거나 운영 서버의 동기화를 중단하는 도구는 아니다.

## 주 앱 또는 Qt가 시작되지 않을 때

`writerpad-recovery.cmd`와 함께 제공된 Python 모듈들을 같은 폴더에 둔다. 이 소스 복구 도구는 Python 3.11이 필요하며 Qt·클라우드 SDK·주 앱을 불러오지 않는다. 이번 PC에 있는 Python을 사용하며 설치 작업은 하지 않았다. EXE 자체가 고장 나도 소스 도구를 사용할 수 있지만 Python 실행 환경까지 고장 난 경우는 이번 검증 범위가 아니다.

`writerpad-recovery.cmd`를 직접 실행하면 번호 선택 안내가 나온다.

1. **저장 위치 확인:** 프로그램 자료 루트를 입력한다. 기본 설치의 경우 `D:\안티그래비티\scratch\집필프로그램` 아래 `작품목록`이며, 사용자 지정 실행환경은 지정한 자료 루트를 사용한다. 이번 작업에서 실제 원고 폴더를 열어 확인한 것은 아니다.
2. **자료 사본 보존:** 원본 작품 폴더와 별도 위치의 새 목적지를 입력한다. identity가 손상돼도 알려진 사용자 자료와 identity 원본 bytes를 보존한다. 복구를 명목으로 빈 DB를 만들거나 원본 파일을 삭제하지 않는다.
3. **백업 검증:** 사본 폴더의 파일 목록과 해시를 검사한다.
4. **새 독립 폴더에 복원:** 검증한 사본을 새 자료 루트로 옮긴다. 정상 v1 백업은 작품 열기 판정까지 확인한다. 단순 자료 보존본은 `preserved_only`이며 구조 복구 완료가 아니다. 그 안의 TXT/MD를 읽거나 복사할 수 있다.

명령줄을 사용하는 경우:

```powershell
python writerpad_recovery.py locate "<프로그램 자료 루트>"
python writerpad_recovery.py preserve "<원본 작품 폴더>" "<존재하지 않는 사본 폴더>"
python writerpad_recovery.py verify "<사본 또는 백업 폴더>"
python writerpad_recovery.py restore "<사본 또는 백업 폴더>" "<존재하지 않는 독립 자료 루트>"
```

복원 위치는 현재 `작품목록` 밖에 정한다. 복원한 identity와 UUID를 그대로 기존 서버에 재연결하거나 원본 실행환경에 합치는 작업은 이 도구에 포함되지 않는다. 원본·기존 목적지를 보존하기 위해 기존 경로는 거부하며, 경로 이탈·링크·junction을 따라 읽거나 쓰지 않는다.

## AI 응답 저장 오류가 표시될 때

새 응답의 비용 기록과 응답 이력 저장을 각각 처리한다. 실패하면 **AI 응답 보존 · 저장 오류** 창에 원래 작품·회차·단계와 생성 결과가 남는다.

- **전체 복사** 또는 **다른 파일로 저장**을 사용한다. 기존 파일은 덮어쓰지 않는다.
- 다른 회차로 이동하거나 새 요청을 시작해도 실패한 이전 응답은 별도 창에 남는다.
- 파일 저장에 실패하거나 저장 대화상자를 취소하면 응답을 유지한다.
- 저장되지 않은 응답을 닫거나 앱을 종료할 때는 미저장 사실을 알린다. 비용 이력을 재시도한다는 이유로 AI를 다시 호출하지 않는다.

메모리 보존은 프로세스 강제 종료·전원 차단까지 견디는 디스크 저장의 대체물이 아니다. 오류 창에서 가능한 별도 위치에 사본을 저장해야 한다.
