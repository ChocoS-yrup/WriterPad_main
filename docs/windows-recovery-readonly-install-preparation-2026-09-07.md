# Windows: 회차 없는 로그인 원장 조회 설치 준비

2026-09-07 KST. 독립 읽기 구현·검증·빌드 완료. **아직 설치하지 않았고 실제 로그인 RPC를 호출하지 않았다.** 앱 종료 후 설치와 원본 보존 확인, 사용자의 읽기 버튼 조작이 남았다. 실제 복구 송신·재전송·관문 개방은 범위 밖이다.

## 변경과 확인

- `read_server_ledger`는 현재 클라이언트로 원장 RPC를 읽고 11필드·식별값·nonce·계정·완전성·정수 count·시각을 검증하는 공통 읽기 함수다. DB 사건을 기록하지 않는다. 독립 조회는 유효한 nonzero count도 결과로 보존하지만 실행 권한을 부여하지 않는다. 기존 복구 adapter는 계속 nonzero를 거절하고 성공한 0건 검사 뒤에만 기존 사건을 기록한다.
- 독립 경로는 원본 준비/기존 stopped 행 검증 및 복구 회차 없음, 닫힌 관문을 확인한다. 앱 현재 클라이언트의 캡처한 JWT를 `auth.get_user(jwt=...)`에 전달해 해당 계정을 확인한다. 이 경로에서 get_session·토큰 갱신·별도 외부 클라이언트 생성은 하지 않는다. 로컬에 설치된 SDK 소스로 명시적 jwt 인자가 get_session 호출을 피하는 것을 확인했다.
- 현재 클라이언트로 새 nonce의 읽기 API를 호출하며, 전후 작품/계정 연결·클라이언트·JWT·쓰기 epoch·관문을 확인한다. 변경된 관찰은 stale이다. 원래 승인이나 과거 proof를 읽기 호출 또는 실행 허가로 재사용하지 않는다.
- `서버 원장 조회 · 회차 생성 없음`과 `원장 조회 결과 내보내기`를 추가했다. 독립 조회는 claim·sender·DB 쓰기·관문 setter를 호출하지 않는다. 읽기 중 복구 sender와 중복 읽기를 차단한다. 결과/오류는 메모리에만 보관하고 작품 밖 JSON으로 내보낸다. 오류 원문이나 토큰은 기록하지 않는다.
- 기존 준비 상태 관찰·내보내기 동작은 유지하고 공통 내보내기 코드만 재사용한다. 새 원장 읽기 결과에는 현재 로그인 조회의 proof와 관찰 시각, stale·원본 보존·회차 유무·execution_authorized=false를 구분하여 담는다. 전체 작품 구조/큐/handshake를 검사했다는 뜻은 아니다.

## 다음 사용자 행동 및 남은 절차

1. 현재 Windows 집필프로그램을 완전히 종료하고 `종료했습니다`라고 보낸다. 새 송신·복구 버튼을 누르지 않는다.
2. Windows 작업이 준비된 설치 절차로 이전 EXE를 백업하고 새 EXE로 교체한다. 읽기 전용 메타데이터 검사로 원본 준비·기존 실행·닫힌 관문·복구 회차 0개를 설치 전후 비교한다. Qt smoke는 정상 앱 실행이나 DB 마이그레이션을 대신하지 않는다.
3. 설치 확인 뒤 앱을 열어 최종검증03/같은 계정에서 **독립 서버 원장 조회 버튼만** 사용하고 `windows-recovery-readonly.json`을 작품 밖에 내보낸다. 정확한 조작 시점은 설치 완료 후 안내한다.
4. 실제 로그인 결과와 설치/원본 보존 근거를 iPad에 보낼 ZIP으로 정리한다. 실제 복구 회차 생성·송신은 진행하지 않는다.
