Windows 사용자가 승인된 4회 화면 조작을 완료하고 앱을 종료했다. 복제본 확인 결과 **대기 19개·충돌/batch/run/실제 서버 요청 0개**이며 기존 ID 5개·본문·초안·완료 원고·보호 파일이 유지됐다. 기존 11개 큐는 그대로이고 추가 8개만 붙었다. 제품 변경·재설치·기존 검사 재실행은 없다.

전달 파일: [test-targets-v2.json](../_evidence/windows-integrated-editor-execution-20260913/exchange/test-targets-v2.json). SHA-256 **`78405ea61ffcc1ae0491676dc63389ba47f46db56586f576f1f78974a3649669`**. 이전 명세 `9e87ad64…`와 파일은 이력으로 보존했으며, 이번 실행의 실제 대상 대조에는 v2를 사용한다.

- **이름 보완:** R=`왕복.txt`, E=`빈문서.txt`, 최종 부모는 둘 다 A. 예상 최종 경로는 `메인/메모장/통합검증 20260913/A/왕복.txt`, `메인/메모장/통합검증 20260913/A/빈문서.txt`다. 실제 서버 `relative_path` 관측값은 아직 없으며 Windows wire가 별도 경로 필드를 보내는 것으로 설명하지 않는다.
- **B 정렬 보완:** E의 A→B→A 이동 2회와 정렬 작업이 실제 큐에 있다. B 정렬 `c225e5a6-4d1a-5e23-969c-60a48332bd18`을 base 0에서 [E]로 생성하고, base 1에서 []로 비우는 순서다. 최종 서버 기대값은 revision 2 / children=[]이며 아직 실제 서버 반영이 아니다.
- **근거:** 실제 추가 8작업의 kind/node/before/after가 동결 후보 직렬화·mock 송수신으로 확인한 보완 절차와 일치한다. 본문·큐·감사 연결도 복제본으로 확인했다. 초기 11개 생성 요청에 확장자 없는 이름이 남아 있으므로 **iPad는 Windows 19쓰기와 후속 수신 완료 신호 전 수신하지 않는다.**

**회신:** v2 해시·이름·B 정렬 송신 계획이 후보와 맞으면 ‘v2 명세 일치·Windows S1 완료 신호까지 첫 수신 대기’만 알려준다. 아직 차단이 있으면 해당 차이만 알린다. 실제 B 정렬 기준과 `.txt` 경로는 S1 이후 iPad 첫 수신에서 확인하고 S2로 넘어간다. 새 설치/전체 검사/큰 ZIP은 필요 없다.
