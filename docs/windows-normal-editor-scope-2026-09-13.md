## 양측 공통 송수신 조건 제안

1. 앱 시작은 통신 잠김 상태다. 로컬 작품·문서 식별은 이름만으로 판단하지 않는다. 계정, Staging endpoint, server project/document UUID, mode/epoch가 일치해야 새 네트워크 동작을 허용한다. 기존 영속 관문·보류를 자동 변경하지 않는다.
2. 로컬 저장은 인증 권한과 분리한다. 본문은 UTF-8, 줄바꿈은 LF로 표현하며 마지막 줄바꿈의 유무를 보존한다. trim, Unicode 정규화, 줄바꿈 자동 추가를 하지 않는다. 수신/송신 대조는 revision·UTF-8 바이트 수·전체 SHA-256을 사용한다. 빈 본문은 이번 범위에서 전송하지 않는다.
3. 큐 등록이 가능한 경우 기존 저장소에 불변 operation을 보존한다. 요청에는 대상 ID, base revision, 내용/해시, operation/batch ID가 결합된다. 관문이 필요한 Windows enqueue는 지정 대상에 한해 복원 기록을 먼저 남기고 임시 변경 후 정확히 복원한다. 로컬 저장 후 큐 등록 실패는 별도 상태로 남겨 다음 실행에서 유실되지 않도록 한다.
4. 사용자가 송신을 요청하면 새 인증/handshake와 대상 기준으로 허용 범위를 확인한다. 큐에서 선택한 지정 문서의 준비된 operation 하나만 보낸다. 뒤에 저장한 내용은 별도 후속 자료로 보존하며 응답 미확정 operation을 수정하거나 새 ID로 복제하지 않는다. 후속 operation의 base 확정은 기존 계약의 불변성 규칙을 따라 2번에서 확인한다.
5. 수신은 지정 문서와 그 계약 검증에 필요한 작품/구조 메타데이터를 읽는다. 다른 문서/구조를 원본에 반영하지 않는다. 미저장 편집, 큐 등록 실패 자료, 미완료 송신이 있으면 원격 본문으로 덮어쓰지 않는다. 로컬 초안·서버 결과를 각각 보존하고 해결 대기로 표시한다. 이번 첫 범위는 양측 순차 편집이며 동시 편집 자동 병합/강제 덮어쓰기는 하지 않는다.
6. 준비 권한이 만료되거나 화면을 벗어나면 새 HTTP를 시작하지 않는다. 이미 시작한 요청은 응답 유무와 실제 반영 여부를 기록한다. 로컬 글·큐·완료 내역은 유지한다. 새 준비는 미완료 동작의 권한만 갱신하며 이전 단계로 초기화하지 않는다. 완료 후 시간 경과로 완료 문구를 오류로 바꾸지 않는다.
7. 표시 상태를 `로컬 저장됨`, `큐 등록 필요`, `송신 대기`, `송신 결과 확인 필요`, `충돌/복구 대기`, `서버 반영 완료`로 구분한다. 마지막 완료 revision은 현재 권한 상태와 별도로 표시한다. 사용자가 실제로 수행한 일보다 넓게 “동기화 완료”라고 표시하지 않는다.
