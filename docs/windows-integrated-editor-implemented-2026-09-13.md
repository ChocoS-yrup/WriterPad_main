# Windows 통합 집필 구현·로컬 검사 결과

후속: 사용자 별도 요청으로 [통합 EXE 패키징·격리 시작 검사](windows-integrated-editor-packaged-2026-09-13.md)를 완료했다. 아래 패키징 전 표시는 이 구현 문서 작성 당시 상태다. 설치·실기기 검증은 아직 진행하지 않았다.

기준: [양측 통합 작업지시서](windows-ipad-integrated-work-order-2026-09-13.md). 후속 사용자 요청 「윈도우측 구현 시작」에 따라 Windows 소스 구현과 격리 검사를 진행했다. 기존 실행안의 승인을 재사용하지 않았다.

**Windows 로컬 구현·검사 완료. 통합 EXE 패키징과 실제 기기/서버 확인은 아직 진행하지 않았다.** 설치·실제 서버 조회/송수신·관문/보류 변경·prod 전환은 없다. 기존 완료 문서의 정상 왕복·종료 감사도 반복하지 않았다.

## 구현

- `integrated_editor_store.py`: 문서 ID별 본문·초안·선택 상태, 순서가 있는 본문/구조 대기 작업, 불변 계약 요청, 결과·충돌·실행 한도를 영속 저장한다. 문서·폴더 생성/이름 변경/이동/정렬/삭제/복원을 지원한다. 폴더 복원은 해당 삭제에 포함된 항목만 복원하여 이전에 따로 삭제한 글을 되살리지 않는다.
- `integrated_editor_sync.py`: 기존 `document_commit`·`atomic_structure_commit` 계약 생성기와 응답 검증기를 재사용한다. 수동·자동 실행을 직렬화하고 Auth·handshake·조회·쓰기·복구 요청을 모두 같은 한도로 계산한다. 모호한 쓰기는 원래 batch의 SELECT receipt 또는 이미 보존된 응답으로만 복구한다. 마지막 허용 요청의 응답은 로컬에 반영하고 다음 요청부터 중단한다.
- `integrated_editor_ui.py`: 기존 `SmartTextEdit` 기반 집필창에 문서 트리·구조 조작·수동/유휴 저장·자동 동기화·충돌 보기를 연결했다. 문서 전환과 종료 시 초안을 보존하고, 한글 조합 중 문서 전환/동기화로 글자를 잃지 않도록 한다. 통신 중에는 화면 편집·구조 조작을 잠시 잠근다.
- `integrated_editor_runtime.py`, `integrated_editor_plan.py`, `main.py`: 별도 통합 후보 시작 경로를 추가했다. 작업 트리 플래그는 **False**다. 기존 `main.py` 수정본을 먼저 보존했고, 이번 변경은 비활성 진입점 추가뿐임을 대조했다. 기존 `normal_editor_*`, `sync_manager.py`, `sync_v2_store.py` 구현은 수정하지 않았다.

통합 후보는 **별도 private SQLite와 UUID별 TXT 복사본**을 사용한다. 기존 원본 DB·완료 원고를 이 새 저장소로 덮어쓰거나 이전 기록을 초기화하지 않는다. 최초 가져오기에서도 원본 DB/WAL/SHM은 파일로 복제·대조한 뒤 복제본만 SQLite로 연다. 초기 가져오기된 기존 항목은 읽기 전용이며, 완료 문서와 그 부모 정렬도 보호한다. 새 문서·폴더와 승인된 원격 시험 ID만 편집·송신 대상으로 삼는다. 기존 일반 앱의 원고 폴더에 새 문서를 직접 투영하는 경로는 이번 통합 후보에 연결하지 않았다.

최초 로컬 시작에는 인증/HTTP가 없다. 이전에 명시적으로 연결한 같은 승인 실행과 자동 동기화 설정이 남아 있을 때만, 전경 복귀 후 유효한 기존 한도로 재개한다. 실제 실행을 위한 `reviewed-execution.json`은 이번에 만들지 않았다. 향후 실행안은 원본 DB·WAL/SHM의 존재 여부/해시, hold·device·완료 본문 등 보존 기준도 포함해야 한다.

충돌은 기준·로컬·초안·원격을 보존하며 자동 병합/해제하지 않는다. 서버가 쓰기를 거절한 뒤에도 명시적 수신으로 원격 충돌 내용을 보존할 수 있다. 상대 기기의 구조 작업 중간 상태를 읽으면 부분 반영하지 않고 기존 한도 안에서 다음 전체 수신을 기다린다.

## 검사

실제 socket 연결·키체인 접근을 차단하고, SQLite 연결을 매 실행의 새 격리 디렉터리로 제한했다. Qt는 offscreen으로 사용했고 스크린샷은 촬영하지 않았다.

**서로 다른 통합 검사 32개와 시작 모드 회귀 검사 11개가 통과했다.** 한 번에 43개를 최종 소스로 재실행했다는 뜻은 아니다. 묶음 검사 후 실패와 변경 영향 범위만 재검사했다.

## 남은 작업과 iPad 전달

1. iPad의 변경점·검사 결과·차단을 대조한 뒤 양측 통합 후보와 구체적인 실행안을 준비한다. 기존 단일 문서 후보와 23회 상한은 재사용하지 않는다.
2. 통합 EXE 패키징/시작 검사와 승인된 양측 Staging 확인이 남아 있다. 실제 receipt SELECT 권한/RLS는 **양측 모두 미확인**이다. 서버 정책/스키마 변경 필요 여부도 실서버 확인 없이 단정하지 않는다.
3. iPad에는 [짧은 변경점·차단](ipad-integrated-editor-windows-brief-2026-09-13.md)만 전달하면 된다. 도구로 직접 발송하지 않았다.

서버 연동은 새 SDK 기능을 도입하지 않고 기존 계약을 사용했다. 참고한 [공식 변경 이력](https://supabase.com/changelog)과 [Data API 권한 문서](https://supabase.com/docs/guides/api/securing-your-api)는 실제 프로젝트 권한 검사 근거가 아니다.
