# iPad 작품 생성·서버 목록·가져오기 검토 요청 — 2026-09-10

이 문서는 사용자가 iPad 개발 측에 전달할 검토 제안이다. 문서 자체는 실기기 조작·서버 변경·설치·실제 송신 승인으로 간주하지 않는다. iPad 소스는 이번 Windows 작업 공간에서 확인하지 못했으므로, 사용자가 보고한 목록 기능 부재를 구현 감사 완료로 표현하지 않는다.

## Windows에서 완료한 일

- 기존 고정 시험 작품의 Windows 로컬 UUID만 서버·DB UUID와 달랐다. 사용자 승인 후 한 항목을 교정했다.
- 설치 앱의 준비 확인 결과와 종료 후 DB 대조: 폴더 11개·정렬표 12개·C9 충족·미완료 0건. 모든 관문 닫힘, 시험 송신 보류 유지, 다른 작품과 기존 작업 기록 보존.
- 별도 재발 방지 수정: Windows 신규 작품 생성 UUID를 첫 동기화 DB 등록 및 서버 등록 요청에서 재사용한다. 격리 검사 100개 통과. 소스 수정만 완료했으며 이 수정의 빌드·설치·실제 송신 검증은 아직 하지 않았다.

## iPad 측 진행 순서

1. 기존 구현과 UI 노출 여부를 먼저 확인한다. 신규 작품 UUID 발급·서버 등록·서버 작품 목록·기존 작품 가져오기 경로의 파일과 함수, 기존 검사 근거를 회신한다. 이미 구현·검증한 기능은 반복 개발하지 않는다.
2. 신규 생성은 작품 UUID를 한 번 발급하여 로컬 저장과 서버 등록이 같은 UUID를 쓰는지 확인한다. 재시작·등록 재시도에서도 새 UUID가 발급되지 않아야 한다. 제목 변경은 작품 ID 변경으로 처리하지 않는다.
3. 서버 작품 목록이 없다면 인증된 사용자의 접근 가능한 작품을 조회하고, UUID를 기준으로 이미 가져온 작품·미가져온 작품·가져오기 중단 상태를 구분하는 흐름을 구현·격리 검증한다. 제목은 표시 정보이며 동명이 다른 작품을 합치지 않는다.
4. 기존 작품 가져오기는 서버 작품 UUID와 문서·폴더 UUID 및 순서를 보존한다. 로컬에 같은 이름의 새 작품을 만든 후 UUID를 수동 덮어쓰는 절차로 대신하지 않는다. 이름 충돌 시 별도 로컬 이름을 선택하거나 중단하고 기존 작품·원고는 보존한다.
5. 가져오기 중단·재시도, 이미 가져온 작품, 같은 이름의 다른 UUID, 다른 로컬 작품에 연결된 UUID, 손상된 identity, 로컬 미완료 변경이 있는 상태를 합성 자료로 검증한다. 가져오기 과정에서 기존 원고를 송신하거나 대기열을 복제하지 않는지도 확인한다.
6. Windows 변경을 검토하고, 양쪽 코드·격리 검사 결과와 실기기 확인만 남은 항목을 구분해 회신한다. 실제 서버 쓰기나 현재 시험 작품을 다시 만드는 작업은 이번 검토 범위에 넣지 않는다.

## 회신에 필요한 내용

- 기준 소스 버전/커밋과 변경 파일, 기존 구현 재사용 여부.
- 작품 생성 → 서버 등록 → 다른 기기 가져오기에서 UUID가 어떻게 유지되는지.
- 검사 이름·결과·네트워크 사용 여부, 남은 미구현 또는 실기기 확인 항목.
- 현재 시험 작품의 관문·송신 보류와 앱 전역 동기화 설정의 의미. 과거 앱 종료 관측을 다음 실행의 OFF 상태로 추정하지 않는다.
- Windows의 신규 등록 시 identity 재사용·충돌 거부 및 기존 연결 유지 정책에 대한 검토 의견.
