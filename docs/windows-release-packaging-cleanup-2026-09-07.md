# 배포 빌드 기준 통일·시험 카드 기본 숨김 완료

2026-09-07 KST. 사용자 ‘진행’에 따라 앞서 남긴 두 코드 작업을 완료했다. 제품의 계약 전송·원장·관문 검사 로직은 변경하지 않았다. 기존 성공 18파일 묶음 위의 후속 변경이며, 수정 파일은 `settings_panel.py`와 `.github/workflows/windows-contract.yml` 두 개다.

## 변경

- CI의 PyInstaller spec을 실제 검증본과 같은 **`작가님힘내세요.spec`**으로 통일하고, 해시 대상도 **`dist/작가님 힘내세요.exe`**로 맞췄다. 기존 spec 파일을 삭제하지 않았다.
- main push 변경 감지에 Python 파일 전체와 실제 spec·스타일·아이콘·모델 목록을 포함했다. 기존 pull_request/workflow_dispatch 및 고정 checkout·계약 검증·전체 시험 단계는 유지했다.
- 빌드 후 `--qt-import-smoke-test`로 프로젝트·인증 초기화 전 Qt 시작을 확인하는 CI 단계를 추가했다. 프로세스는 숨김으로 시작하며 비정상 종료 코드는 CI 실패로 남는다. 단계 제한은 2분이다. 후속 단계가 EXE 크기·SHA256을 기록한다.
- 일반 설정에서는 **최종검증03 전용 검토 카드와 그 안의 버튼 11개를 기본 숨김** 처리한다. 기존 일반 동기화 진단 새로고침·복사는 유지한다.
- 전용 카드가 필요한 진단 환경에서만 프로세스 환경변수 **`WRITERPAD_CONTRACT_REVIEW_UI=1`**로 표시할 수 있다. 미설정·빈 값·`0`·`true`는 표시하지 않는다. CI에서는 `0`을 명시한다. 제품 설정 파일이나 시스템 환경변수를 이번 작업에서 변경하지 않았다.
- 이 값은 UI 표시 조건일 뿐 실행 승인이나 보안 권한이 아니다. 별도 승인·고정 요청·중단 이력·새 회차 최대 1개·관문·송신 직전 검사는 그대로다. 과거 성공한 시험을 다시 실행할 용도로 사용하지 않는다.

## 필요한 확인 결과

- 실제 제품의 카드 구성 코드를 격리된 Qt offscreen 부모에 실행해 **5개 환경값**을 확인했다. 기본 모드에서 카드와 버튼 11개가 모두 보이지 않고, 정확한 `1`에서만 표시된다. 일반 진단 표시는 모두 유지되며 구성/표시 과정의 작업 호출은 0회다. 제품 SyncManager나 실제 프로필은 초기화하지 않았다. 화면 캡처는 하지 않았다.
- workflow YAML 파싱, 빌드→Qt 검사→해시 기록 순서와 경로 일치, 기존 checkout·고정 계약 검증·시험 단계 불변을 확인했다.
- workflow의 모든 run 블록을 PowerShell 파서로 확인했다. 구문 오류가 없으며 해당 명령을 실제 실행한 것은 아니다.
- 변경 구문과 `git diff --check`를 통과했다. 작업 전 두 파일에 후속 패치를 격리 재적용해 현재 내용과 대조했다.
- 이전 성공 후보의 나머지 **17개 파일**은 해시가 그대로다. 설치 EXE **`7b9c0eacc75da121afe02ddbe8784b9dc09cc37a6c1175ee4024b2d4d5b0fc73`**도 유지됐다.

기존 140개 시험이나 두 실제 고정 계약을 반복하지 않았다. CI 실제 성공을 주장하지 않으며 원격 CI 실행, 새 빌드·설치·커밋·푸시, 앱·DB·서버 조작, 송신·관문 개방은 하지 않았다. CI의 새 Qt 단계는 향후 해당 workflow가 실행될 때 빌드된 새 EXE를 검사한다.

## 결과와 다음 행동

소스 변경은 완료됐지만 **현재 설치된 앱에는 아직 카드 숨김 변경이 반영되지 않았다.** 기존 성공 설치본을 계속 보존했다.

사용자가 지금 앱을 종료하거나 iPad에 ZIP을 보낼 필요는 없다. 다음 적용 단계는 앞서 준비한 성공 18파일 기준과 이번 2파일 변경을 구분해 커밋하고, 새 빌드/CI 결과를 확인한 뒤 설치하는 것이다. 같은 `settings_panel.py`가 두 단계에 걸쳐 있으므로 전체 후보의 고유 파일 수는 **19개**다. 이 후속 변경을 과거 성공 EXE와 동일한 바이트라고 표시하지 않는다.

정식 외부 배포의 서버 환경·서명 방식은 여전히 별도 결정 사항이다. 이 UI/CI 정리가 Production 전환이나 계약 관문 상시 개방을 뜻하지 않는다.
