# Windows 일반 본문 검증 후보 준비

이번 사용자 승인은 Windows 독립 준비(코딩·격리 검증·미설치 후보 빌드)에만 적용했다. 이전 문서의 설치·송신 승인 기록을 새 실행 권한으로 사용하지 않았다.

## 구현

- 일반 시험 작품 전용 창을 일반 앱 시작보다 먼저 실행한다. 창 표시만으로 인증·DB·동기화를 시작하지 않는다. 자동 송신, 재시도, 수신 조정기, Realtime 또는 복구 작업을 생성하지 않는다.
- 버튼별 새 5분 권한으로 저장된 로그인과 Auth 서버의 사용자를 대조한다. 계정·토큰·장치·로컬 작품 연결을 계속 확인하며, 창 이탈·최소화·종료 시 중지한다.
- 기존 `ID_BASED / epoch 1`을 요구한다. 실제 관문 활성화와 명시적인 송신 보류 해제 기록 없이는 쓰기를 거부한다. 관문·보류를 바꾸는 기능은 이 후보에 없다.
- 매 단계 handshake와 지정 작품 5개 표만 읽는다. 소유자, 기존 제어 문서, 11개 폴더, 12개 UUID 정렬표, 본문 상태를 대조한다. HTTP 직전과 응답 수용 직후 파일·저장소 상태를 다시 대조한다.
- 본문 생성에는 기존 생성 거래를, 저장에는 기존 비교 저장을, 송신에는 기존 큐·계약 생성·시도·영수증 처리를 사용한다. 런타임 operation/batch ID를 그대로 고정한다.
- 본문 생성과 정렬 저장은 별도 RPC다. 중간 실패·응답 유실 시 파일과 시도 기록을 보존하고 중지한다. 같은 단계의 재실행은 지속 기록으로 막는다.
- Windows 화면의 `<root>`는 실제 `메인` 내부를 표시하므로 UUID 정렬표와 화면 설정을 각각 대조한다. 실제 설정은 읽어서 표현을 확인했으며 변경하지 않았다.
- 전체 폴더 검사를 저장 중에도 유지하기 위해 비교 저장에 선택적 `temporary_guard`를 추가했다. 이번 저장이 소유한 정확한 임시 파일만 전달하며, 다른 임시 파일은 제외하지 않는다. 기존 호출 방식은 유지된다.

## 검증과 한계

격리 검사 33개 통과. 새 실행 시험 13개와 변경된 HTTP 경계 관련 20개다. 실제 SDK를 가짜 HTTP에 연결하고 실제 제품 SQLite·파일 거래를 임시 디렉터리에서 실행했다. 네트워크 연결과 격리 영역 밖 SQLite 열기는 차단했다. 성공 경로, 타 작품 큐 보존, 관문·보류 거부, 계정·파일 변경, 중도 권한 종료, 응답 유실, 본문 생성 후 정렬 실패, 재시작 버튼 복원을 검증했다.

빌드 입력·실행 파일 대조 및 시작 시험 결과는 `_evidence/windows-general-runtime-candidate-20260912/`에 보존한다. 설치 파일·실제 DB·보류 기록 변경과 실제 서버 요청은 수행하지 않았다. 완료된 LEGACY 왕복 시험과 UUID 교정·이전 설치 검사를 다시 실행하지 않았다.

이는 격리 검증된 후보이며 실제 서버·장치 왕복 성공을 의미하지 않는다. iPad 전용 화면·인증·실행 제한 구현 완료 확인이 남아 있다. 실제 실행 전에 후보 해시, 설치 범위, 지정 작품 관문·보류의 일시 변경과 종료 시 복원 절차를 구체화하여 한 번의 실행 범위로 승인받아야 한다. 이 문서는 실행 승인이 아니다.

## 승인받을 실행 범위 초안

대상은 `일반동기화 검증 20260910` 한 작품, `general-body-20260912-v1` 한 본문이다. ID·본문·해시는 기존 합의 그대로다. prod 전환·LEGACY 작품 변경·iPad 수신 전용 후보 변경은 없다.

|순서|담당|행동과 성공 조건|
|---|---|---|
|1|양측 개발|iPad 구현 완료 결과와 Windows 후보를 대조하고 설치·관문·보류 복원까지 포함한 실행 범위 확정|
|2|사용자 승인 후 Windows|후보 설치, 버튼 1로 인증·새 기준 확인. 관문·보류는 별도로 승인된 제한 절차로 준비|
|3|Windows|버튼 2. 본문 create 1회 → revision 1/100 bytes. 부모 order 1회 → revision 2/[문서 UUID]. 읽기 재대조 후 iPad로 인계|
|4|iPad|본문 1·정렬 2 수신. 합의 문장 추가·송신 1회 → 본문 revision 2/128 bytes|
|5|Windows|버튼 3. 본문 2 수신·대조, 합의 문장 추가·송신 1회 → 본문 revision 3/159 bytes|
|6|iPad와 Windows|iPad 최종 revision 3 수신, 양측 5줄 대조·종료. 승인된 관문·보류 복원 및 오프라인 결과 확인|

Windows 네트워크 상한: 각 버튼 Auth 사용자 조회 최대 4회·필요 시 refresh 1회, handshake 각 1회. 5개 표 전체 조회는 버튼 1에서 1회분, 버튼 2에서 3회분, 버튼 3에서 2회분. Windows 쓰기는 document_commit 2회와 atomic_structure_commit 1회로 제한한다. ID_BASED 경로에 lease RPC는 없다. 실패 시 다음 단계로 넘어가지 않는다.

교환 자료는 `ipad-next-general-runtime-request-20260912.md` 한 장이면 된다. 소스·전체 로그·과거 ZIP은 기본 전송 대상에서 제외한다.
