### 구현 순서와 완료 조건

1. **서버 목록:** 로그인한 계정이 접근 가능한 작품을 UUID 기준으로 조회하고 가져옴·미가져옴·중단·연결 충돌 상태를 표시한다. 같은 이름의 다른 UUID는 합치지 않는다. 계정/연결 변경 뒤 이전 응답을 사용하지 않는다. 실제 개발 시 현재 API와 권한을 확인한다.
2. **수신용 생성 journal:** 선택한 서버 UUID와 로컬 binding 정책을 최초 journal에 기록한다. 일반 신규 작품 생성 후 ID를 덮어쓰거나 임의 UUID의 표준 폴더를 먼저 만들어 서버 구조와 섞지 않는다. 중단·재시도는 같은 journal과 ID로 재개한다. 기존 작품의 ID 필드를 일괄 교정하지 않는다.
3. **기존 snapshot 재사용:** 폴더·문서·순서·revision 검증과 적용이 끝난 후에만 작품을 편집 가능한 완료 상태로 노출한다. 수신 중 일반 송신 coordinator에 넘기지 않는다. 이름 충돌은 별도 로컬 이름 선택 또는 중단으로 처리하며 서버 제목을 바꾸지 않는다.
