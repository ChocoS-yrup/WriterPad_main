## 요청·설정·중단 범위

Windows는 기본 순서의 네 번의 준비/송신 동작마다 새 인증·최대 5분 전경 권한과 handshake 1회를 사용한다. 동작별 Auth 사용자 조회 최대 4회, 필요한 refresh 최대 1회다. 지정 작품 5개 표 전체 조회는 네 동작에 **1/2/1/2세트**, 합계 **30 GET**이고 문서 update는 **2회**다. 수동 저장·유휴 자동저장 자체는 네트워크 요청이 없다. 일반 dispatcher·자동 재시도·Realtime·lease·구조 쓰기는 실행하지 않는다.

iPad는 위 로그인·기준 확인·실행 준비와 **수신 버튼 2개 각각 1회, 저장·송신 버튼 1회**만 수행한다. iPad 내부 Auth/조회 HTTP 총수는 이번 요약 보고에 없으므로 Windows 수치로 추정하지 않는다. 이 범위는 해당 후보의 전용 버튼 동작을 승인하는 것이며 일반 동기화 개방을 승인하는 것은 아니다.

Windows 저장 두 번에만 대상 행의 `contract_path_enabled`, `contract_path_enabled_at`, `updated_at`을 임시 변경한다. undo를 먼저 보존하고 **저장이 끝나면 송신 전에 원래 값으로 복원**한다. 송신 시 관문은 닫혀 있다. Windows 전역 hold 파일은 전 과정에서 수정하지 않는다. iPad는 영속 설정·관문·보류를 변경하지 않고, 프로세스 한정 자동 실행 억제와 임시 권한만 사용한다. 이미 켜진 iPad 관문을 임의로 닫지 않는다.

실행·편집 중에는 해당 창을 유지한다. 오류·만료·창 이탈·불일치 시 중지하고 마지막 성공 단계와 오류를 전달한다. 저장/송신 시도 기록을 삭제·초기화하거나 버튼을 재클릭하지 않는다. 원본 파일과 큐의 반영 여부를 확인한 뒤 남은 단계만 판단한다. **쓰기 시도가 전혀 없었던 읽기 전용 준비**는 기록 확인 후 같은 범위에서 새 인증·handshake·동일 기준 조회로 재준비할 수 있으며, 새 회차 기록을 보존한다. 이는 자동 재시도나 완료된 송신 반복을 허용하지 않는다. 관문 복원은 만료·실패 후에도 인증 없이 수행한다.
