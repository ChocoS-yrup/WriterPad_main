# iPad 오프라인 바인더 검토 완료 — 2026-09-11

**최초가져오기** (`d21b8876-e93e-42d3-a792-8f49c5471be9`)의 오프라인 화면 관찰을 완료로 인정한다. 사용자 관찰은 “최초가져오기 바인더 정상, 원고 앞·휴지통 마지막, 오류 없음”이다. 원고가 없는 시험 작품의 화면 확인이며 본문 수신·양방향 동기화 완료를 의미하지 않는다.

입력 ZIP SHA-256: `f9ebebf0006d3824121b822e8fae8ada85b89b149ce1477cc2292c0936ab8897`. 26개 manifest 파일의 크기·해시, 정확한 집합, CRC와 경로를 확인했다. 원본 승인 기록과 요청 ZIP 해시는 Windows 전달 자료와 일치한다. authorization.json의 `authorized_not_executed`는 요청 당시 사본이고, 실행 결과는 별도 launch/completion 기록에 있다.

사전 상태 JSON은 이전 최초 수신 사후 상태와 정확히 일치한다. 명시적 실행은 1회이며 2026-09-11 09:41:51 KST 실행, 사용자 관찰 기록 09:42:53, 사후 종료 확인 09:43:03 순서다. 관찰 파일 작성 시각을 실제 메시지 제출 시각으로 단정하지 않는다.

동기화 DB 16개 테이블의 행 수·digest, 설정과 수신 journal은 전후 동일하다. 대상 폴더 11개·일반 원고 0개·내부 정렬 문서 1개, 대상 송신 작업 0이 유지됐다. Documents 파일은 추가·삭제·내용 변경이 없다고 보고됐다. 정책 해시도 이전 승인 후보와 일치한다.

메타데이터 DB는 완전히 동일하지 않다. 대상 폴더 10행의 경로 표기·수정 시각·Z_OPT, 최근 작품 선택 1행, 관련 이력 11/2행과 PK 카운터가 변경됐다. 경로는 NFC 정규화 후 동일하고, 새 수정 시각은 실행 전 디렉터리 시각과 1초 이내로 일치한다. 변경 필드·행 수와 29개 검사 조건의 결과가 서로 부합한다. 이는 iPad 사후 자료 대조 29개이며 Windows에서 실행한 XCTest 29개가 아니다.

Windows는 제공된 결과와 감사 소스 7개를 검토했다. 비공개 DB·전체 파일 목록이 없으므로 실제 기기 자료로 29개 조건을 재실행하지 않았다. 디렉터리 감사 코드는 정규화된 키를 사전으로 만들면서 중복을 명시적으로 거부하지 않으므로 ‘유일한 경로’라는 검사 이름만으로 원본 경로의 중복 부재까지 독립 입증하지는 않는다. 수신 자료 훼손을 나타내는 증거는 없으며 이 한계를 보존한다.

iPad가 설명한 scanner/reconcile 동작은 관측된 필드 변경과 부합한다. 다만 Windows에 있던 과거 두 binder 소스는 최종 후보 manifest 해시와 달랐다. 과거 소스를 최종 후보의 직접 증거로 사용하지 않으며, 이번 판정은 사용자 관찰과 전후 대조 기록에 근거한다. 제품 코드 추가 수정이나 재수신은 하지 않는다.

준비 중 대상 앱 프로세스가 다시 존재해 종료한 기록이 있다. 재등장 원인은 미확정이며, 이후 통제된 실행·종료가 성공했다고 해서 해결됐다고 보지 않는다. 마지막 종료는 해당 관측 시점의 사실이다. 무선 차단은 사용자 확인 및 호스트 전달 차단 근거이며 패킷 실측은 없다.

다음은 **기존 로컬 자료만으로 본문 수신 시험 대상과 절차를 준비**하는 단계다. 실제 온라인 수신·시험 자료 업로드·설치·송신·관문 변경·prod 전환은 이 문서로 승인되지 않는다. 양쪽 앱을 추가 조작할 일은 없다. 사용자는 함께 준비한 다음 요청 ZIP을 iPad 담당에게 전달하고 회신을 이 작업에 첨부하면 된다.
