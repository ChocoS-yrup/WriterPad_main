# iPad 전달 — 두 차단의 Windows 보완안

검토용·수정 실행 범위 승인 전이다. 실제 데이터/서버는 변경하지 않았다.

- 이름은 표시만 줄인 것이 아니다. 동결 직렬화도 `왕복`/`빈문서`이며 `relative_path`는 wire에 없다. Windows에서 같은 ID를 `왕복.txt`/`빈문서.txt`로 이름 변경하는 안으로 정정한다.
- B의 빈 정렬 자동 생성에 기대지 않는다. 같은 E를 **A→B→A**로 옮겨 B 정렬을 명시적으로 생성한 뒤 비운다. 기존 후보를 쓰며 최종 T=[A,B], A=[R,E], B=[]와 본문은 유지한다.
- 복제본+동결 후보+mock transport에서 **추가 8개, 초기 총 19쓰기**, B 정렬 revision 1 [E] → revision 2 []를 확인했다. 실제 서버 성공 증거는 아니다. 기존 11개 큐·실제 ID·명세는 덮어쓰지 않는다.
- 수정 제안: Windows 쓰기 21 / HTTP 280 / Auth 계획 30, iPad 26 / 520 / 16 유지, 양측 HTTP 총 800. 실행 ID·12:30 KST 절대 만료 유지. 사용자 승인 후 실제 4회 화면 조작과 새 명세를 준비한다.
- iPad는 **Windows S1 19쓰기 및 후속 수신 완료 전 수신 금지**를 유지한다. 수정 명세에서 `.txt` 이름을 대조하고, 첫 수신에서 실제 경로와 B 정렬 기준까지 확인한 뒤 S2를 시작한다. S2~S7과 iPad 작업 수는 바꾸지 않는다.

상세: [차단 보완안](windows-ipad-integrated-blocker-correction-2026-09-13.md). 추가 제품 수정·전체 재검사·재설치 요청은 없다. 이 내용에 실제 후보 제약과 다른 차단이 있을 때만 알려준다. 실제 새 명세는 아직 생성하지 않았다.
